Neural network architectures: CNNs, RNNs, LSTMs and beyond

A plain neural network treats its input as a flat list of numbers. Images and sequences have structure, and specialised architectures are built to exploit it. This guide covers convolutional networks for images, transfer learning, a first look at object detection and segmentation with YOLO, and recurrent networks (RNN, LSTM, GRU) for text and time series, with Keras code and interactive demos throughout.

Neurons, activation functions, backpropagation and optimisers are covered in the companion page Deep learning foundations. This page assumes you have read it.

1Why different architectures?

Intuition. The shape of your data decides the shape of your network. A network that "knows" pixels next to each other belong together, or that word order matters, learns far faster and from far less data than one that has to discover it.

Recap: the dense network (MLP)

A dense (fully connected) layer connects every input to every neuron: output = activation(W·x + b). Stack a few and you have a multi-layer perceptron (MLP). It's a good fit for tabular data, but it has no idea which inputs are "near" each other, so it treats pixel (0, 0) and pixel (27, 27) as equally related.

Data type → architecture

Data typeShape of one exampleStructure to exploitGo-to architecture
Tabular (a spreadsheet row)(features,)None in particular: column order is arbitraryGradient boosting first; an MLP if you must use deep learning
Images(height, width, channels)Nearby pixels are related; a cat is a cat wherever it sits in the frameCNN (convolutional neural network); Vision Transformers for very large datasets
Text(tokens,) → embeddings (tokens, dim)Order matters; meaning depends on contextTransformers today; RNN / LSTM / GRU historically and for small problems
Time series(time steps, features)Order matters; the past predicts the futureGradient boosting on lag features, LSTM / GRU, 1-D CNNs, transformers
AudioWaveform (samples,) or spectrogram (time, freq)Local patterns in time and frequencyCNN on spectrograms, transformers
Video(frames, height, width, channels)Images that change over timeCNN per frame + RNN / transformer, or 3-D CNNs

The built-in assumption a model makes about the data is called its inductive bias. CNNs assume locality (nearby things matter together) and translation invariance (a pattern means the same thing wherever it appears). RNNs assume order and that the same processing applies at every step. When those assumptions match reality, the model learns quickly.

2Images as data

Intuition. To a computer, an image is just a grid of numbers: one number per pixel for a greyscale image, three per pixel (red, green, blue) for a colour image.

  • A pixel is one point in the grid. Its value is usually 0 (black) to 255 (white) for each channel.
  • A channel is one layer of the grid. Greyscale has 1 channel; colour (RGB) has 3.
  • So an image is a 3-D array, or tensor, of shape (height, width, channels). A batch of images adds a fourth dimension in front: (batch, height, width, channels).
Dataset / imageShapeNumbers per image
MNIST / Fashion-MNIST (greyscale)(28, 28, 1)784
CIFAR-10 (small colour photos)(32, 32, 3)3,072
Typical ImageNet model input(224, 224, 3)150,528
A 12-megapixel phone photo(3000, 4000, 3)36 million

Always scale pixels before training, usually to 0–1 by dividing by 255 (or to whatever range a pretrained model expects). Raw 0–255 values make training unstable.

Why not just flatten the image and use a dense network? Two reasons. First, flattening throws away the 2-D layout: the pixel above another one ends up 28 positions away in the list. Second, the number of weights explodes with image size (see section 5). Convolution fixes both.

3Convolution

Intuition. Slide a small "pattern detector" across the image. At each position, it scores how strongly that patch matches its pattern. The grid of scores is a map of where the pattern appears.

The vocabulary

  • Kernel (or filter): a small grid of weights, typically 3×3 or 5×5. These weights are learned during training.
  • Convolution: place the kernel on a patch of the image, multiply each pixel by the matching kernel weight, add everything up (plus a bias). That one number is the output for this position. Then slide along and repeat.
  • Stride: how many pixels the kernel moves each step. Stride 2 skips every other position and roughly halves the output size.
  • Padding: adding a border of zeros around the image so the kernel can sit on the edge pixels. "valid" = no padding (the output shrinks); "same" = pad so that, with stride 1, the output is the same size as the input.
  • Feature map (or activation map): the output grid from one filter. A layer with 32 filters produces 32 feature maps, stacked as 32 channels.

The output size formula

    
For an input of width W, kernel size K, padding P (zeros added on each side) and stride S:

    
output = (W − K + 2P) / S + 1

    
If the division isn't whole, round down. The same formula applies to the height.

    

      
Input WKernel KPadding PStride SCalculationOutput

      
        
2830 (valid)1(28 − 3 + 0)/1 + 126

        
2831 (same)1(28 − 3 + 2)/1 + 128

        
28501(28 − 5 + 0)/1 + 124

        
32312(32 − 3 + 2)/2 + 1 = 15.5 + 1 → round down16

        
224732(224 − 7 + 6)/2 + 1 = 111.5 + 1 → round down112

      
    

    
The depth (number of channels) of the output is simply the number of filters. Each filter spans all input channels: a 3×3 filter on a 3-channel RGB image is really 3×3×3 = 27 weights plus one bias.

    
Small print: what deep-learning libraries call "convolution" is, strictly, cross-correlation (the kernel isn't flipped). Since the weights are learned anyway, it makes no practical difference.


    
What do filters learn?

    
Nobody hand-designs the kernels in a CNN: training finds them. But when researchers visualise trained networks, a clear hierarchy appears:

    

      
Layer 1
edges, colour blobs
→
      
Layers 2–3
corners, textures, simple shapes
→
      
Middle layers
parts: eyes, wheels, petals
→
      
Deep layers
whole objects: faces, cars

    

    
Each layer combines patterns from the layer below. A neuron deep in the network "sees" a large area of the original image: its receptive field. Two stacked 3×3 convolutions see a 5×5 area; three see 7×7. Pooling and strides grow it faster.


    
Activation after convolution

    
Convolution is a weighted sum, so it's linear. Each convolution is followed by a non-linear activation, almost always ReLU (max(0, x)), which keeps positive responses ("the pattern is here") and zeroes out negative ones. Try the Apply ReLU button in the explorer with the vertical-edge kernel: only one side of each edge survives.

4Pooling and the classifier head

    
Intuition. Pooling shrinks a feature map by summarising each small window with one number. It keeps "is the pattern roughly here?" and throws away "exactly which pixel?".


    
    
      
  • Max pooling keeps the largest value in each window: the strongest response. The usual choice between conv blocks.
    • 
      
  • Average pooling keeps the mean of each window: a smoother summary.
    • 
      
  • The standard setting is a 2×2 window with stride 2, which halves the height and width (and so quarters the number of values) and has no weights to learn.
    • 
    

    
Why pool? It cuts computation for the layers that follow, grows the receptive field, and makes the network a little tolerant of small shifts: if an edge moves by one pixel, the max of its window often stays the same.

From feature maps to a prediction: flatten vs global average pooling

    
After the conv/pool blocks you have a 3-D block of feature maps, for example 7 × 7 × 64. A classifier needs a flat vector, so you either:

    

      
Flatten
Unroll the block into one long vector: 7 × 7 × 64 = 3,136 numbers, then a Dense layer.
Keeps position information, but the next Dense layer is large (3,136 × 128 + 128 = 401,536 weights) and prone to overfitting.

      
Global average pooling (GAP)
Average each feature map down to one number: 7 × 7 × 64 → 64 numbers.
Far fewer weights, less overfitting, works with any input size. The standard choice in modern CNNs and for transfer learning.

The pattern: the spatial size shrinks (28 → 14 → 7) while the number of channels grows (1 → 32 → 64). The network trades "where" for "what". The first part is the feature extractor (or backbone); the Dense layers at the end are the head.

5Parameter sharing: why CNNs are so efficient

    
Intuition. A vertical-edge detector that works in the top-left corner works everywhere. So a CNN uses the same small set of weights at every position, instead of learning separate weights for every pixel.

    
Two ideas make convolution cheap:

    
    
      
  • Local connectivity: each output looks at a small patch (3×3), not the whole image.
    • 
      
  • Parameter sharing: the same kernel weights are reused at every position.
    • 
    

    
Counting the parameters

    
For a Conv2D layer:

    
params = (kh · kw · in_channels + 1) · filters

    
The "+ 1" is each filter's bias. Notice what is not in the formula: the image size. A conv layer has the same number of weights for a 28×28 image as for a 4000×3000 one.

    
For a Dense layer: params = (inputs + 1) · units.


    

      
Worked example, 28×28×1 input (Fashion-MNIST):

      
    
        
  • Conv2D, 32 filters of 3×3, "same" padding → output 28×28×32. Params = (3 · 3 · 1 + 1) · 32 = 320.
    • 
        
  • Dense layer producing the same 28×28×32 = 25,088 outputs from the 784 inputs. Params = (784 + 1) · 25,088 = 19,694,080. That's over 60,000 times more.
    • 
        
  • Even a modest Dense(128) on the flattened image needs (784 + 1) · 128 = 100,480 weights, and it only makes 128 outputs.
    • 
        
  • Second conv layer, 64 filters of 3×3 on the 32-channel input: (3 · 3 · 32 + 1) · 64 = 18,496.
    • 
      

    

    
Fewer parameters means less memory, faster training, and above all less overfitting: the model can't memorise individual pixel positions.

6A full CNN in Keras: Fashion-MNIST

    
Intuition. Two conv/pool blocks to find patterns, dropout to stop memorisation, a small dense head to make the decision. This recipe gets around 90%+ test accuracy on 10 clothing classes in a few minutes on a laptop.

    
Fashion-MNIST is 70,000 greyscale 28×28 images of clothing in 10 classes (T-shirt, trouser, pullover, dress, coat, sandal, shirt, sneaker, bag, ankle boot): 60,000 for training, 10,000 for testing. It's a drop-in, harder replacement for handwritten-digit MNIST.


import numpy as np
import keras
from keras import layers          # with TensorFlow 2.x you can also write: from tensorflow import keras

# 1. Load and prepare the data
(x_train, y_train), (x_test, y_test) = keras.datasets.fashion_mnist.load_data()
x_train = x_train.astype("float32")[..., None] / 255.0   # (60000, 28, 28, 1), values 0–1
x_test  = x_test.astype("float32")[..., None] / 255.0    # [..., None] adds the channel axis
class_names = ["T-shirt/top", "Trouser", "Pullover", "Dress", "Coat",
               "Sandal", "Shirt", "Sneaker", "Bag", "Ankle boot"]

# 2. Build the model
model = keras.Sequential([
    keras.Input(shape=(28, 28, 1)),
    layers.Conv2D(32, kernel_size=3, padding="same", activation="relu"),
    layers.MaxPooling2D(pool_size=2),
    layers.Conv2D(64, kernel_size=3, padding="same", activation="relu"),
    layers.MaxPooling2D(pool_size=2),
    layers.Dropout(0.25),
    layers.Flatten(),
    layers.Dense(128, activation="relu"),
    layers.Dropout(0.5),
    layers.Dense(10, activation="softmax"),     # one probability per class
])
model.summary()

# 3. Compile: labels are integers 0–9, so use the "sparse" cross-entropy
model.compile(optimizer="adam",
              loss="sparse_categorical_crossentropy",
              metrics=["accuracy"])

# 4. Train, holding back 10% for validation; stop when validation loss stops improving
history = model.fit(
    x_train, y_train,
    epochs=15, batch_size=128, validation_split=0.1,
    callbacks=[keras.callbacks.EarlyStopping(patience=3, restore_best_weights=True)],
)

# 5. Evaluate once on the test set, then predict
test_loss, test_acc = model.evaluate(x_test, y_test)
probs = model.predict(x_test[:5])          # shape (5, 10): probabilities
preds = probs.argmax(axis=1)               # most likely class index
print([class_names[i] for i in preds])

Notice where the weights are: the two conv layers have under 19,000 parameters; the Dense layer after Flatten has over 400,000. That's why modern CNNs replace Flatten() with GlobalAveragePooling2D(): here that would turn 3,136 inputs into 64, and a Dense(10) straight after it needs only 650 weights.

ChoiceWhy

Optional extras: layers.BatchNormalization() after each conv layer often speeds up and stabilises training (see Deep learning foundations).


    
Data augmentation

    
Intuition. Show the model slightly different versions of each training image (flipped, rotated, zoomed) so it learns that a shoe is still a shoe when it's tilted. It's like getting more data for free.


augment = keras.Sequential([
    layers.RandomFlip("horizontal"),
    layers.RandomRotation(0.05),          # up to ±5% of a full turn (about ±18°)
    layers.RandomZoom(0.1),               # zoom in or out by up to 10%
    layers.RandomTranslation(0.1, 0.1),   # shift up to 10% vertically and horizontally
])

model = keras.Sequential([
    keras.Input(shape=(28, 28, 1)),
    augment,                              # active during fit() only; does nothing in predict()/evaluate()
    layers.Conv2D(32, 3, padding="same", activation="relu"),
    # ... the rest as before
])

    
    
      
  • Augmentation is applied on the fly, so each epoch sees different versions of each image.
    • 
      
  • It is only for training. Never augment the validation or test set.
    • 
      
  • Choose realistic transformations. Horizontal flips are fine for clothes and cats, wrong for digits or text (a flipped "2" isn't a "2"), and vertical flips rarely make sense for photos. In medical imaging, check with a domain expert.

7Transfer learning

    
Intuition. Don't learn to see from scratch. Borrow a network that has already learned edges, textures and object parts from millions of photos, and only teach it the last step: your classes.

    
Big models such as ResNet50, MobileNetV2 and EfficientNet have been trained on ImageNet (about 1.3 million photos in 1,000 classes). Their early and middle layers detect general visual features that are useful for almost any image task. Transfer learning reuses those layers.


    
The recipe

    
    
      
  1. Load the pretrained base without its original 1,000-class head (include_top=False).
    2. 
      
  2. Freeze the base (base.trainable = False) so its weights don't change.
    3. 
      
  3. Add a new head: global average pooling → (dropout) → a Dense layer with your number of classes.
    4. 
      
  4. Train only the head with a normal learning rate.
    5. 
      
  5. Optionally fine-tune: unfreeze the top layers of the base and keep training with a very small learning rate (e.g. 1e-5), so the pretrained features adjust gently instead of being wrecked.
    6. 
    


    
Input requirements, plainly: ImageNet models expect colour images (3 channels) of a reasonable size (MobileNetV2 and ResNet50 need at least 32×32 and were trained at 224×224). Fashion-MNIST is 28×28 with 1 channel, so you must resize it up (e.g. to 96×96) and copy the grey channel three times to fake RGB. Each model also expects its own pixel scaling: use that model's preprocess_input function or match its range yourself.



import keras
from keras import layers

# Pretrained MobileNetV2 without its classifier head
base = keras.applications.MobileNetV2(input_shape=(96, 96, 3), include_top=False, weights="imagenet")
base.trainable = False                               # step 2: freeze

inputs = keras.Input(shape=(28, 28, 1))              # Fashion-MNIST, pixels scaled to 0–1
x = layers.Resizing(96, 96)(inputs)                  # 28×28 → 96×96
x = layers.Concatenate()([x, x, x])                  # 1 grey channel → 3 identical "RGB" channels
x = layers.Rescaling(2.0, offset=-1.0)(x)            # 0–1 → −1…1, the range MobileNetV2 expects
x = base(x, training=False)                          # keep BatchNorm layers in inference mode
x = layers.GlobalAveragePooling2D()(x)
x = layers.Dropout(0.2)(x)
outputs = layers.Dense(10, activation="softmax")(x)  # step 3: new head
model = keras.Model(inputs, outputs)

model.compile(optimizer=keras.optimizers.Adam(1e-3),
              loss="sparse_categorical_crossentropy", metrics=["accuracy"])
model.fit(x_train, y_train, epochs=5, validation_split=0.1)          # step 4: train the head

# Step 5 (optional): fine-tune the top of the base with a tiny learning rate
base.trainable = True
for layer in base.layers[:-30]:                      # keep all but the last 30 layers frozen
    layer.trainable = False
model.compile(optimizer=keras.optimizers.Adam(1e-5),  # recompile after changing trainable
              loss="sparse_categorical_crossentropy", metrics=["accuracy"])
model.fit(x_train, y_train, epochs=5, validation_split=0.1)

    
To use ResNet50 instead, swap in keras.applications.ResNet50(...) and its own preprocessing, keras.applications.resnet50.preprocess_input, which expects pixel values in 0–255.


    

      
Your situationStrategy

      
        
Small dataset, similar to ImageNet photos (pets, products)Freeze the base, train the head only. Fine-tune lightly if you have time

        
Large dataset, similar imagesTrain the head, then fine-tune more layers

        
Small dataset, very different images (X-rays, satellite)Still start pretrained (edges are edges), but expect to fine-tune more, and validate carefully

        
Large dataset, very different imagesFine-tune the whole network, or train from scratch

      
    

    
Honest note: on Fashion-MNIST, the small CNN from section 6 is already about as good and much faster, because tiny grey images are very unlike ImageNet photos. Transfer learning shines on real photos with only hundreds or a few thousand labelled examples, where training from scratch would badly overfit.

    

      
Strengths
  • Good accuracy with little data
  • Much faster training
  • Strong, tested architectures for free

      
Watch out for
  • Must match the expected input size, channels and scaling
  • Large models are slow on CPUs and phones
  • Fine-tuning with a high learning rate destroys the pretrained features

    

  


  
  

    
8Beyond classification: detection, segmentation and YOLO

    
Intuition. Classification asks "what is in this picture?". Detection asks "what, and where (a box)?". Segmentation asks "which exact pixels belong to what?".


    

      
TaskOutputExample questionTypical models

      
        
Image classificationOne label (or probabilities) for the whole image"Is this a photo of a dog?"CNNs (ResNet, EfficientNet), Vision Transformers

        
Object detectionFor each object: a bounding box (x, y, width, height), a class and a confidence"Where are the cars and pedestrians?"YOLO, Faster R-CNN, SSD, DETR

        
Semantic segmentationA class for every pixel; objects of the same class are not separated"Which pixels are road, sky, building?"U-Net, DeepLab

        
Instance segmentationA separate pixel mask for each individual object"Outline each person separately"Mask R-CNN, YOLO "-seg" models

        
Pose estimationKeypoints (joints) for each person or object"Where are this runner's knees and elbows?"YOLO "-pose" models, OpenPose

      
    


    

    
How YOLO works, in brief

    
YOLO ("You Only Look Once") is a family of real-time object detectors. Older detectors first proposed thousands of candidate regions and then classified each one. YOLO instead runs the image through a CNN backbone once and, in that single forward pass, predicts boxes, class probabilities and confidence scores across a grid of positions and scales. That's why it's fast enough for live video.

    
    
      
  • Bounding box: the rectangle around an object.
    • 
      
  • Confidence: how sure the model is that the box contains that object. You set a threshold (e.g. 0.25) to drop weak boxes.
    • 
      
  • IoU (intersection over union): how much two boxes overlap, from 0 (none) to 1 (identical). Used to judge whether a predicted box matches the true one, and to remove duplicates.
    • 
      
  • Non-maximum suppression (NMS): the traditional clean-up step that keeps the most confident box and removes heavily overlapping duplicates of the same object.
    • 
      
  • mAP (mean average precision): the standard detection metric, averaging precision over classes and IoU thresholds.
    • 
      
  • Segmentation models ("-seg") add a mask branch, so each detected object also gets a pixel-level mask.
    • 
    


    
Running a pretrained Ultralytics YOLO model

    
The Ultralytics Python package is the most popular way to use YOLO. It provides pretrained models for detection, segmentation, classification and pose, mostly trained on the COCO dataset (80 everyday classes: person, car, dog, cup…). Model names encode size and task: n, s, m, l, x go from nano (fastest) to extra-large (most accurate), and a suffix such as -seg, -cls or -pose picks the task. Ultralytics releases new generations regularly, so check its documentation for the current model names.


# pip install ultralytics
from ultralytics import YOLO

model = YOLO("yolo11n-seg.pt")      # pretrained nano segmentation model (weights download on first use)
results = model("image.jpg")        # one forward pass: boxes, classes, confidences and masks

r = results[0]                      # one result per image
print(r.boxes.xyxy)                 # box corners (x1, y1, x2, y2) in pixels
print(r.boxes.cls, r.boxes.conf)    # class ids and confidence scores
print(r.names)                      # class id → name, e.g. {0: "person", ...}
masks = r.masks                     # per-object masks (None for detection-only models)
r.save(filename="result.jpg")       # save the image with boxes and masks drawn on it

    
To detect your own classes, you fine-tune a pretrained model on labelled images (boxes or masks drawn with an annotation tool), described in a small YAML file: YOLO("yolo11n.pt").train(data="my_data.yaml", epochs=50, imgsz=640). That's transfer learning again.

9Recurrent neural networks (RNNs)

    
Intuition. Read a sequence one item at a time, like you read a sentence, keeping a running summary in your head. The summary (the hidden state) is updated at every word and passed on to the next step.


    
Sequences

    
A sequence is data where order matters: the words in a sentence, daily sales, heartbeat readings, notes in a melody. "Dog bites man" and "man bites dog" contain the same words but mean different things. Each item is a time step; the item at step t is written xt.


    
The hidden state

    
At each step an RNN combines the new input xt with its previous hidden state ht−1:

    
ht = tanh(Wx·xt + Wh·ht−1 + b)

    
The hidden state ht is a vector of numbers (for example 64 of them) that acts as the network's memory of everything seen so far. The key point: the same weights Wx, Wh and b are used at every step. That's parameter sharing again, this time across time instead of across space, and it means an RNN can handle sequences of any length.


    
Unrolling through time

    
An RNN is one cell applied in a loop. Drawing the loop out, one copy of the cell per time step, is called unrolling:

    

      
x₁ → cell
h₁ →
      
x₂ → cell
h₂ →
      
x₃ → cell
h₃ →
      
…
→
      
xT → cell
→
      
hT
summary of the whole sequence

    

    
Training uses backpropagation through time (BPTT): ordinary backpropagation run backwards through the unrolled copies. You can try the unrolled network step by step in the widget in section 10.


    
The vanishing-gradient problem

    
To learn that the first word of a long review matters to the final prediction, the error signal (the gradient) has to travel back through every step. At each step it is multiplied by the recurrent weights and by the slope of tanh, which is at most 1. Multiply many numbers smaller than 1 together and the result shrinks towards zero: 0.520 ≈ 0.000001.

    
    
      
  • Vanishing gradients: the signal from distant steps fades away, so a plain RNN effectively only remembers the last 10–20 steps. It can't learn long-range dependencies.
    • 
      
  • Exploding gradients: the opposite, if the factors are larger than 1, the gradients blow up and training becomes unstable. The usual fix is gradient clipping (e.g. keras.optimizers.Adam(clipnorm=1.0)).
    • 
    

    
The LSTM and GRU were designed specifically to fix the vanishing-gradient problem.


layers.SimpleRNN(64)                          # returns only the last hidden state: shape (batch, 64)
layers.SimpleRNN(64, return_sequences=True)   # returns every hidden state: shape (batch, time steps, 64)

    
Input shape for all Keras recurrent layers: (batch, time steps, features per step).

  


  
  

    
10LSTM: long short-term memory

    
Intuition. Give the network a separate long-term memory, a "conveyor belt" running along the sequence, plus three gates that decide what to forget, what to write, and what to read out at each step.


    
The cell state: a conveyor belt

    
An LSTM keeps two vectors: the usual hidden state ht (short-term, what it outputs now) and a cell state ct (long-term memory). The cell state runs along the whole sequence with only small, controlled changes at each step: some information is removed, some added. Because the cell state is updated mostly by adding, rather than being squashed and multiplied by a weight matrix at every step, gradients can flow back along it over long distances without vanishing.


    
The three gates, in plain words

    
A gate is a small layer with a sigmoid activation, so it outputs values between 0 ("block everything") and 1 ("let everything through"). Each gate looks at the current input and the previous hidden state.

    

      
GateQuestion it answersExample in "Not a good film overall"

      
        
Forget gate ft"How much of the old memory should I keep?" (1 = keep it all, 0 = wipe it)Stays close to 1 through "a", "film", "overall", so the negation from "Not" is kept

        
Input gate it + candidate c̃t"What new information is worth writing to memory, and how much of it?" The candidate is the proposed new content; the input gate decides how much of it gets writtenHigh at "Not" (store the negation) and at "good"; low at "a"

        
Output gate ot"Which part of my memory is relevant to output right now?"High at the last word, when the final sentiment is read out

      
    

    
So at each step: forget part of the old memory, add the gated new candidate, then read out a filtered version as the new hidden state.


    

      Show the LSTM equations
      
Here [ht−1, xt] means the previous hidden state and current input joined into one vector, σ is the sigmoid function and ⊙ is element-wise multiplication.


f_t  = σ(W_f · [h_{t−1}, x_t] + b_f)        # forget gate
i_t  = σ(W_i · [h_{t−1}, x_t] + b_i)        # input gate
c̃_t  = tanh(W_c · [h_{t−1}, x_t] + b_c)     # candidate memory
c_t  = f_t ⊙ c_{t−1}  +  i_t ⊙ c̃_t          # new cell state: keep some old, add some new
o_t  = σ(W_o · [h_{t−1}, x_t] + b_o)        # output gate
h_t  = o_t ⊙ tanh(c_t)                      # new hidden state

      
Four sets of weights (f, i, c̃, o), each of size units × (inputs + units) plus a bias, so an LSTM layer has 4 × units × (inputs + units + 1) parameters: four times a SimpleRNN of the same size. The ct = ft ⊙ ct−1 + … line is the conveyor belt: when ft ≈ 1, memory and gradient pass through almost unchanged.

11GRU and bidirectional RNNs

    
Intuition. A GRU is a slimmed-down LSTM: one memory instead of two, and two gates instead of three. It usually performs about as well, with fewer parameters.


    
The GRU's two gates

    
    
      
  • Update gate zt: "how much should I replace my memory with new content?" It does the jobs of the LSTM's forget and input gates in one: whatever fraction it lets in, it removes the same fraction of the old state.
    • 
      
  • Reset gate rt: "how much of the past should I look at when proposing new content?" A value near 0 lets the cell ignore the old state and start fresh.
    • 
    

    
There is no separate cell state: the hidden state ht is the memory.

    

      Show the GRU equations

z_t = σ(W_z · [h_{t−1}, x_t] + b_z)              # update gate
r_t = σ(W_r · [h_{t−1}, x_t] + b_r)              # reset gate
h̃_t = tanh(W_h · [r_t ⊙ h_{t−1}, x_t] + b_h)     # candidate state, using the "reset" past
h_t = (1 − z_t) ⊙ h_{t−1}  +  z_t ⊙ h̃_t          # blend old and new

      
Some texts swap the roles of z and 1 − z; the idea is identical. Three sets of weights instead of four, so roughly 25% fewer parameters than an LSTM of the same size.

    


    
LSTM vs GRU

    

      
Simple RNNLSTMGRU

      
        
GatesNone3: forget, input, output2: update, reset

        
MemoryHidden state onlyHidden state + separate cell stateHidden state only (gated)

        
Long-range memoryPoor (vanishing gradients)GoodGood

        
Parameters (64 units, 1 input feature, Keras)4,22416,89612,864

        
SpeedFastest per stepSlowestBetween the two

        
Reach for it whenTeaching, or very short sequencesLong sequences, plenty of data; the safe defaultSmaller data or tighter compute; often matches the LSTM

      
    

    
Parameter formulas: SimpleRNN u(d + u + 1); LSTM 4u(d + u + 1); Keras's GRU 3u(d + u + 2) (its default reset_after=True adds a second bias), where u = units and d = input features. In practice, try both and let validation decide; the difference is usually small.


    
Bidirectional RNNs

    
A normal RNN reads left to right, so at word 3 it knows nothing about word 4. A bidirectional RNN runs two RNNs, one forwards and one backwards, and joins their outputs, so every position sees context from both sides.

    

      
"The bank of the river"
→
      
forward LSTM →
← backward LSTM
→
      
"bank" now knows about "river"
outputs concatenated: 2 × units

    


layers.Bidirectional(layers.LSTM(64))    # output size 128 (64 forwards + 64 backwards)

    
Only when the whole sequence is available up front. Bidirectional is great for classifying or tagging complete texts. It's wrong for forecasting, where the "future" half of the sequence isn't known at prediction time; using it there leaks the answer.

Time-series forecasting with sliding windows

    
A neural network needs fixed-size (input, target) pairs. For a single series, cut it into overlapping windows: the last 30 values are the input, the next value is the target. Slide forward one step and repeat.

    

      
t₁ … t₃₀ → t₃₁

      
t₂ … t₃₁ → t₃₂

      
t₃ … t₃₂ → t₃₃

      
…

    


import numpy as np
import keras
from keras import layers

def make_windows(series: np.ndarray, window: int = 30, horizon: int = 1):
    """Each X is `window` past values; y is the value `horizon` steps after the window."""
    X, y = [], []
    for start in range(len(series) - window - horizon + 1):
        X.append(series[start:start + window])
        y.append(series[start + window + horizon - 1])
    return np.array(X)[..., None], np.array(y)      # X: (samples, window, 1 feature)

# `series` is a 1-D NumPy array in time order, e.g. daily sales
split = int(len(series) * 0.8)                      # chronological split: never shuffle before splitting
train, test = series[:split], series[split:]
mean, std = train.mean(), train.std()               # scale using TRAINING statistics only
train_s, test_s = (train - mean) / std, (test - mean) / std

X_train, y_train = make_windows(train_s, window=30)
X_test,  y_test  = make_windows(test_s,  window=30)

model = keras.Sequential([
    keras.Input(shape=(30, 1)),                     # 30 time steps, 1 feature per step
    layers.LSTM(64),
    layers.Dense(1),                                # a number, so no activation
])
model.compile(optimizer="adam", loss="mse", metrics=["mae"])
model.fit(X_train, y_train, epochs=50, batch_size=32,
          validation_split=0.1,                     # Keras takes the LAST 10%, so validation is later in time
          callbacks=[keras.callbacks.EarlyStopping(patience=5, restore_best_weights=True)])

pred = model.predict(X_test).ravel() * std + mean   # back to the original units
naive = test[29:-1]                                 # baseline: "tomorrow = today"
print("LSTM MAE: ", np.abs(pred - test[30:]).mean())
print("Naive MAE:", np.abs(naive - test[30:]).mean())

    
Time-series traps: split by time, never randomly (a random split lets the model peek at the future). Fit any scaling on the training period only. And always compare with a naive baseline ("tomorrow = today", or "same day last week"): LSTMs often fail to beat it, and gradient boosting on lag features is frequently a stronger, simpler choice for tabular-style forecasting.

    
For several input features (temperature, day of week, promotions…), stack them as the last axis: (samples, window, n_features). To predict several steps ahead at once, use Dense(horizon) and targets of that length. Keras also has a helper, keras.utils.timeseries_dataset_from_array, that builds windows efficiently for large series.

    
Stacking recurrent layers: every recurrent layer except the last needs return_sequences=True so the next one receives a full sequence: LSTM(64, return_sequences=True) → LSTM(32) → Dense(1).

  


  
  

    
13How transformers replaced RNNs

    
Intuition. Instead of passing a memory along word by word, let every word look directly at every other word and decide which ones matter. That's attention, and it's what powers modern large language models.

    
RNNs have two built-in limits:

    
    
      
  • They are sequential. Step 100 can't be computed until step 99 is done, so they can't use a GPU's parallelism well and are slow to train on huge datasets.
    • 
      
  • Long-range memory is still hard. Even an LSTM squeezes everything it has read into one fixed-size vector, and information from far back still fades.
    • 
    

    
The transformer (2017, "Attention Is All You Need") drops recurrence altogether. With self-attention, every token computes how relevant every other token is and builds its new representation as a weighted mix of them. The first word and the last word are one step apart, and all positions are processed in parallel. Word order is added back with positional encodings. This made it practical to train on internet-scale text, giving BERT, GPT and today's large language models. Vision Transformers apply the same idea to image patches.

    

      
RNN / LSTM / GRUTransformer

      
        
ProcessingOne step at a timeAll positions in parallel

        
Distance between two wordsGrows with their separationAlways one attention step

        
Data and compute needsModestLarge (but pretrained models are freely available)

        
Cost on very long inputsGrows linearly with lengthStandard attention grows with length squared

      
    

    
Where RNNs still make sense: small datasets, streaming data processed one reading at a time on a small device, low-latency sensor or signal processing, and as a simple, well-understood baseline for time series.
