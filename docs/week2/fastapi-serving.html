Serving models with FastAPI: URLs, ports, endpoints and status codes

A trained model in a notebook helps nobody else. This guide explains, from the ground up, how other programs talk to a model over HTTP: what a URL is made of, what IP addresses, localhost and ports are, how routes, methods and status codes work, and how to build and test a FastAPI service that serves your MLflow champion model.

1Why put a model behind an API?

Intuition. An API turns your model into a service, like a shop counter: anyone who knows the address can walk up, hand over the inputs and get a prediction back, without knowing anything about Python, scikit-learn or how the model was trained.

An API (application programming interface) is a defined way for one program to ask another program to do something. A web API does this over HTTP, the same protocol your browser uses to load web pages. You send a request to an address; the API sends back a response, usually in JSON (a plain-text format for data that almost every language can read).

Without an API

  • The model lives in a notebook or a .pkl file on one laptop.
  • Every app that wants predictions must load the file itself, in Python, with the same library versions.
  • Updating the model means copying a new file to every app.
  • No central place to log, monitor or secure usage.

With an API

  • The model lives in one place, loaded once into a running server.
  • Any language can call it: a JavaScript web page, a Java back end, Excel, a Streamlit dashboard, another team's service.
  • Swap in a new champion model and every caller benefits immediately.
  • One place to add validation, logging, monitoring and authentication.

2How the web works in one picture

Intuition. The web is a conversation with strict turn-taking: a client asks (a request), a server answers (a response). The server never speaks first.

  • The client is whatever starts the conversation: your browser, curl in a terminal, a Python script using httpx, a Streamlit app.
  • The server is a program that is always running and listening for requests. For us that is uvicorn (a fast Python web server) running our FastAPI app.
  • The request says what you want (the method, e.g. POST), where (the URL) and optionally sends data (the body).
  • The response says how it went (a status code, e.g. 200) and returns data (the body).

An everyday analogy we'll keep using: the IP address is the building's street address; the port is the flat or door number; the route (path) is which desk inside; the method is what you want to do at that desk (ask a question, hand in a form); the body is the form you hand over; the status code is the stamp the receptionist puts on your reply.

Each request is independent: HTTP is stateless, so the server does not remember previous requests unless you build that in. This is a good thing for model serving: any copy of the server can answer any request.

DNS: turning names into numbers

Computers find each other by IP address, but people prefer names. DNS (the Domain Name System) is the internet's phone book: when you request https://api.example.com, your computer first asks a DNS server "what is the IP address of api.example.com?", gets back something like 93.184.215.14, and then connects to that address. The name localhost is special: it is answered by your own computer (from its hosts file) without asking DNS, and always means "this machine".

4IP addresses, localhost and 0.0.0.0

Intuition. An IP address is a building's street address on a network. 127.0.0.1 is the special address that always means "this building, the one I'm standing in".

IPv4 addresses

An IP address (Internet Protocol address) identifies a device on a network. The classic form, IPv4, is four numbers from 0 to 255 separated by dots, for example 192.168.1.20. Each number is one byte (8 bits), so there are 232 ≈ 4.3 billion possible addresses, which is not enough for every device on Earth. That shortage is why private addresses exist.

RangeKindMeaning
127.0.0.0 – 127.255.255.255loopback"This computer". Traffic never leaves the machine. 127.0.0.1 is the one everyone uses.
10.0.0.0 – 10.255.255.255privateUsed inside organisations and cloud networks (e.g. an AWS VPC).
172.16.0.0 – 172.31.255.255privateAlso private; Docker's internal networks often use 172.17.x.x. Note 172.32.0.1 is not private.
192.168.0.0 – 192.168.255.255privateHome and office routers. Your laptop on Wi-Fi is probably 192.168.x.x.
169.254.x.xlink-localSelf-assigned when no router gave you an address. Usually a sign something is wrong.
0.0.0.0unspecified"No particular address". For a server, it means "listen on every network interface" (see below).
Everything elsepublicReachable across the internet, e.g. 8.8.8.8 (a Google DNS server).

Private addresses only work inside their own network, like internal extension numbers in an office. Many homes all use 192.168.1.20 at the same time without conflict. The router translates between private addresses and its one public address (this is called NAT, network address translation).

IPv6 in one paragraph

IPv6 is the newer, much larger address format: eight groups of hexadecimal digits separated by colons, e.g. 2001:db8::8a2e:370:7334 (:: squashes a run of zeros). It has 2128 addresses, enough to give every device a public address. The IPv6 loopback is ::1. In a URL an IPv6 address goes in square brackets so its colons aren't confused with the port: http://[::1]:8000/health. You will mostly meet it when localhost resolves to ::1 instead of 127.0.0.1.

localhost and 127.0.0.1: "this computer"

localhost is a name; 127.0.0.1 is the address it normally points to. Both mean the loopback interface: a virtual network connection from your computer to itself. Requests to it never touch Wi-Fi or the internet, which makes it perfect for development: http://127.0.0.1:8000 and http://localhost:8000 reach the same server on your laptop.

"localhost" is relative. It always means "the machine this code is running on". Inside a Docker container, localhost is the container itself, not your laptop. If your Streamlit container calls http://localhost:8000, it is looking for the API inside the Streamlit container and will fail. Use the other container's service name instead (e.g. http://api:8000 in Docker Compose).

0.0.0.0 vs 127.0.0.1 when starting a server

When you start a server you choose which network interfaces it listens on (this is called binding). A computer has several interfaces: the loopback (127.0.0.1), Wi-Fi (e.g. 192.168.1.20), maybe Ethernet and Docker networks.

--host 127.0.0.1 (uvicorn's default)

Listens only on loopback. Only programs on the same machine can connect. Safe default for development: nobody on the café Wi-Fi can reach your API.

--host 0.0.0.0

Listens on all interfaces. Other machines can connect using any of this machine's addresses. Required inside Docker: traffic arrives at the container's network interface, not at its loopback, so a server bound to 127.0.0.1 inside a container is unreachable from outside.

# only this machine can call it (development)
uvicorn main:app --host 127.0.0.1 --port 8000

# anyone who can reach this machine can call it (Docker, servers, a colleague on your network)
uvicorn main:app --host 0.0.0.0 --port 8000

Why can't I open http://0.0.0.0:8000? 0.0.0.0 is a listening instruction ("any address"), not a real destination. When uvicorn prints Uvicorn running on http://0.0.0.0:8000, you should browse to http://127.0.0.1:8000 or http://localhost:8000 (or the machine's real IP from another computer). Some systems (macOS, Linux) quietly treat 0.0.0.0 as "this machine" and it seems to work; Windows and many browsers refuse it. Don't rely on it.

5Ports

Intuition. If the IP address is the building, the port is the flat number. One computer runs many servers at once (an API, Streamlit, Jupyter, MLflow); each one listens behind its own numbered door.

A port is a number from 0 to 65535 that identifies one listening program on a machine. Only one program at a time can listen on a given port and address. Ports below 1024 are "well-known" and usually need administrator rights to use; for development you pick numbers above 1024.

So on one laptop you might have, all at once: the API at http://localhost:8000, the Streamlit front end at http://localhost:8501, and the MLflow UI at http://localhost:5000. Same building, three different doors.

macOS note: on recent macOS versions the AirPlay Receiver also listens on port 5000, which can clash with mlflow ui. Use mlflow ui --port 5001 or turn off AirPlay Receiver.

"Address already in use"

If you start a server on a port that something else is already listening on, it fails straight away. This is what we saw from uvicorn while testing this page:

ERROR:    [Errno 48] error while attempting to bind on address ('127.0.0.1', 8851): address already in use

(On Linux the error number is 98; on Windows it says "only one usage of each socket address is normally permitted".) Usually the culprit is your own earlier server still running in another terminal. Two fixes:

  1. Choose another port: uvicorn main:app --port 8001.
  2. Find and stop the process holding the port:
# macOS / Linux: who is listening on port 8000?  (-nP prints numbers, not names)
lsof -nP -i :8000
kill <PID>            # polite stop; use kill -9 <PID> only if it refuses

# Windows (Command Prompt or PowerShell)
netstat -ano | findstr :8000      # the last column of the LISTENING line is the PID
taskkill /PID <PID> /F

For example, this is what lsof -nP -iTCP:8873 -sTCP:LISTEN printed for one of our test servers (some columns trimmed). The second column, 61667, is the process ID to pass to kill:

COMMAND     PID   USER   FD   TYPE  ...  NAME
python3.1 61667 samuel    9u  IPv4  ...  TCP 127.0.0.1:8873 (LISTEN)

6Routes, endpoints and parameters

Intuition. Once you're through the right door (port), the path says which desk you want. A route is a desk the app has set up; an endpoint is a desk plus the kind of request it accepts plus the person (function) who deals with it.

TermMeaningExample
PathThe part of a specific URL after the host and port, before ?/customers/42
RouteA path pattern registered in the app, which may contain placeholders/customers/{customer_id}
EndpointA route + an HTTP method + the Python function that handles itGET /customers/{customer_id} → get_customer()

In everyday speech people use "route" and "endpoint" interchangeably. The distinction matters when one path has several methods: GET /v1/models (list models) and POST /v1/models (register a model) are one route, two endpoints.

from fastapi import FastAPI

app = FastAPI()

@app.get("/health")                      # endpoint: GET /health  -> health()
def health() -> dict:
    return {"status": "ok"}

@app.post("/v1/process")                 # endpoint: POST /v1/process -> process()
def process(...): ...

Three ways to send inputs

Query parameter/customers?limit=10&country=UKOptional settings, filters, paging, flags such as debugThe argument is a simple type (int, str, bool…) not in the route
Request bodyJSON sent after the headersLarger or structured data: the model's input featuresThe argument's type is a Pydantic model

app = FastAPI(title="Hello API")

    return {"message": "Hello from FastAPI"}


@app.get("/items/{item_id}")
def read_item(item_id: int, debug: bool = False) -> dict:
    return {"item_id": item_id, "debug": debug}

Notice how FastAPI converted the text "42" from the URL into the integer 42 and "true" into True, purely from the type hints. And "loc":["path","item_id"] tells the caller exactly where the bad input was.

Versioning: why /v1/?

Other people's code depends on your API's exact shape. If you rename a field from tenure_months to tenure, every caller breaks. Putting a version in the path lets you make breaking changes safely:

  • Keep /v1/process working exactly as before.
  • Add /v2/process with the new shape. Callers move over when they're ready.
  • Announce a date, then retire /v1.

Adding a new optional field is not a breaking change and doesn't need a new version. Removing or renaming fields, changing types, or changing what a field means does. Note the API version (v1) is not the same as the model version (registry version 7): you can retrain and swap models many times behind the same /v1 contract, as long as the inputs and outputs keep the same shape.

7HTTP methods

Intuition. The method is the verb of the request: read something, send something, replace, edit or delete it. Same desk, different requests.

MethodMeaningHas a body?SafeIdempotentExample
GETRead / fetchNo✅✅GET /health, GET /v1/models/churn
POSTSend data to be processed; create somethingYes❌❌POST /v1/process, POST /v1/jobs
PUTReplace a whole resourceYes❌✅PUT /v1/thresholds/churn with the full new config
PATCHChange part of a resourceYes❌Usually notPATCH /v1/thresholds/churn with {"threshold": 0.4}
DELETERemoveRarely❌✅DELETE /v1/jobs/17
  • Safe = it doesn't change anything on the server. You can call it as often as you like, and browsers, caches and crawlers will happily do so.
  • Idempotent = doing it twice has the same effect as doing it once. Deleting job 17 twice still leaves job 17 deleted. Sending "create a new order" twice creates two orders, so POST is not idempotent. Idempotent requests are safe to retry after a network glitch.

Why prediction endpoints use POST

A prediction doesn't change anything, so in theory it could be a GET with the features in the query string. In practice almost everyone uses POST with a JSON body, because:

  • Model inputs are often large or nested (many features, lists, a batch of rows, text). URLs have practical length limits of a few thousand characters.
  • A JSON body keeps types (numbers, booleans, lists); a query string is all text.
  • URLs end up in logs, browser history and proxies. Customer data in a URL leaks; data in a body is far less exposed.
  • FastAPI validates a JSON body against a Pydantic model and documents it automatically.

If you call an endpoint with a method it doesn't support, FastAPI answers 405 Method Not Allowed and includes an allow header listing the methods that would work.

Headers

Headers are Name: value labels with information about the message. Names are case-insensitive. The ones you'll meet most:

HeaderDirectionMeaning
Content-Type: application/jsonboth"The body is JSON." Without it on a request, the server may not parse your body as JSON (see the warning below).
Accept: application/jsonrequest"I'd like JSON back."
Content-LengthbothSize of the body in bytes. Set automatically by clients.
Authorization: Bearer … / X-API-Key: …requestCredentials. Headers, not URLs, are the place for secrets.
Allow: POSTresponseSent with 405: which methods this route accepts.
Location: …responseSent with redirects (3xx) and sometimes 201: where to go next.
Retry-After: 30responseSent with 429 or 503: wait this many seconds before retrying.
X-Request-IDbothA unique ID per request, so a caller's complaint can be matched to your logs.

Body and JSON

The body carries the data. For APIs this is almost always JSON (JavaScript Object Notation), which maps neatly onto Python: objects {} ↔ dict, arrays [] ↔ list, strings ↔ str, numbers ↔ int/float, true/false ↔ True/False, null ↔ None. JSON is stricter than Python: keys must use double quotes, and no trailing commas are allowed.

Forgetting the Content-Type header is a classic mistake. curl -d '...' without -H "Content-Type: application/json" sends the body as a web form. We tried it: FastAPI read the body as one long string and answered 422 with "type":"model_attributes_type", "msg":"Input should be a valid dictionary or object to extract fields from". Python clients avoid this if you pass json=payload (not data=), which sets the header for you.

9Status codes

Intuition. The status code is the receptionist's stamp on your reply. The first digit tells you who to blame: 4xx = the client's fault (fix your request), 5xx = the server's fault (fix the server, or try later).

ClassMeaningWhat the caller should do
1xx Informational"Received, carry on." Rare in APIs.Nothing; handled by libraries.
2xx SuccessIt worked.Use the response.
3xx RedirectionIt's somewhere else.Follow the Location header (most clients can do this automatically).
4xx Client errorYour request was wrong: bad address, bad data, not allowed.Fix the request. Retrying the same request gives the same error (except 429).
5xx Server errorThe request looked fine, but the server failed.Not your fault. Retry later, and tell the API owner.

The codes you'll actually meet

CodeNameWhen you'd see it in our API

201CreatedA POST that creates something with its own ID (e.g. a batch job).
204No ContentSuccess with nothing to return (e.g. a DELETE).

401UnauthorizedMissing or wrong API key. (Despite the name, it means "not authenticated": we don't know who you are.)
403ForbiddenWe know who you are, but you're not allowed (e.g. a read-only key calling the reload endpoint).

405Method Not AllowedRight path, wrong verb: GET /v1/process.

400 vs 422: who decides?

Both mean "your input was wrong", but they come from different places in a FastAPI app:

422: FastAPI decides, automatically

Before your function runs, FastAPI parses the JSON and checks it against your Pydantic model. If anything fails (broken JSON, missing field, wrong type, value outside ge/le), FastAPI returns 422 with a list of every problem. Your function never runs.

Think: "the form is filled in wrongly".

400: your code decides

The data passed validation, but it breaks a business rule that types alone can't express: e.g. an annual contract for a customer with 3 months' tenure. You raise HTTPException(status_code=400, detail=...) yourself, with a clear message.

Think: "the form is filled in correctly, but what it asks for doesn't make sense".

The 422 body has a fixed shape. This is a real response from our API for {"tenure_months": 3}, with explanatory notes added on the right (they are not part of the JSON):

{
  "detail": [
    {
      "type": "missing",                         // machine-readable error type
      "loc": ["body", "monthly_charges"],        // where: in the body, field monthly_charges
      "msg": "Field required",                   // human-readable message
      "input": {"tenure_months": 3}              // what was received at that level
    },
    {
      "type": "missing",
      "loc": ["body", "support_calls"],
      "msg": "Field required",
      "input": {"tenure_months": 3}
    }
  ]
}

Constraint errors also include ctx with the limit that was broken, e.g. "ctx": {"le": 50}. A 400 from your own HTTPException has a simpler shape: {"detail": "An annual contract needs tenure_months >= 12"}. Some teams convert 422s to 400s with a custom exception handler so all input errors share one code; either is fine, as long as you're consistent and document it.

10FastAPI basics

Intuition. You write ordinary Python functions with type hints; decorators like @app.get("/health") attach them to URLs. FastAPI handles the HTTP, the JSON and the validation; uvicorn is the server that listens on the port.

11Building the course API step by step

Intuition. A good model API does four jobs in order: check the input, check it's able to answer, predict, and report clearly when anything goes wrong, using the right status code each time.

The course API has two endpoints, as in Thursday's session:

  • GET /health: "Are you alive, and is the model loaded?" Used by people, monitoring and load balancers.
  • POST /v1/process: send a customer's features, get back a churn probability.

For a self-contained example we first train a toy churn model and save it with joblib. In section 13 we replace this file with the MLflow champion.

# train_model.py
import joblib
import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(42)
X = np.column_stack([
    rng.integers(0, 72, 500),          # tenure_months
    rng.uniform(20, 120, 500),         # monthly_charges
    rng.integers(0, 10, 500),          # support_calls
])
y = ((X[:, 2] > 4) | (X[:, 0] < 6)).astype(int)   # toy "churn" label

model = make_pipeline(StandardScaler(), LogisticRegression()).fit(X, y)
joblib.dump(model, "model.joblib")
print("saved model.joblib")

Step 1: load the model once, at startup

A lifespan function runs code when the server starts (before the yield) and when it shuts down (after it). Loading here means the model is read from disk once, not on every request. If loading fails, we log it and let the app start anyway, so /health can report the problem instead of the whole service vanishing.

@asynccontextmanager
async def lifespan(app: FastAPI):
    try:
        state["model"] = joblib.load("model.joblib")   # load ONCE at startup
    except Exception:
        logger.exception("Could not load model")    # app still starts; /health reports it
    yield
    state["model"] = None                             # runs on shutdown


app = FastAPI(title="Churn API", version="1.0.0", lifespan=lifespan)

Step 2: describe the input and output with Pydantic

Step 3: the health endpoint

@app.get("/health")
def health(response: Response) -> dict:
    loaded = state["model"] is not None
    if not loaded:
        response.status_code = 503                    # load balancers read the code
    return {"status": "ok" if loaded else "unavailable",
            "model_loaded": loaded,
            "model_version": MODEL_VERSION if loaded else None}

Why 503 and not 200 with "model_loaded": false? Because machines (load balancers, Kubernetes, AWS health checks) mostly look at the status code, not the body. 503 tells them "don't send traffic here yet". We still return a helpful body for humans. Adding a response: Response argument lets you change the status code while returning normal data.

Step 4: the prediction endpoint, with every error path

@app.post("/v1/process", response_model=ChurnResponse, status_code=200)
def process(req: ChurnRequest) -> ChurnResponse:
    model = state["model"]
    if model is None:
        raise HTTPException(status_code=503, detail="Model not loaded")

    # Business rule: valid JSON and valid types, but it makes no sense -> 400
    if req.contract == "annual" and req.tenure_months < 12:
        raise HTTPException(status_code=400,
                            detail="An annual contract needs tenure_months >= 12")

    X = np.array([[req.tenure_months, req.monthly_charges, req.support_calls]])
    try:
        proba = float(model.predict_proba(X)[0, 1])
    except Exception:
        logger.exception("Prediction failed")          # full details go to the log...
        raise HTTPException(status_code=500,            # ...not to the caller
                            detail="Internal server error")

    return ChurnResponse(churn_probability=round(proba, 4),
                         will_churn=proba >= 0.5,
                         model_version=MODEL_VERSION)
  • req: ChurnRequest makes FastAPI read the JSON body and validate it. Invalid input → 422 before this function even starts.
  • status_code=200 on the decorator sets the success code (200 is the default; you'd use 201 for an endpoint that creates something).
  • raise HTTPException(status_code=..., detail=...) stops the function and sends that code with {"detail": ...}.
  • response_model=ChurnResponse checks and filters what we return, and documents it in /docs.

Never leak stack traces. If an exception escapes your function, FastAPI already returns a plain-text Internal Server Error with status 500 (we checked: content-type: text/plain), and the traceback appears only in the server log. Catching it yourself, as above, gives callers a consistent JSON error and lets you log useful context. Never put str(e) or a traceback in detail: it can expose file paths, library versions, SQL or customer data.

13Serving the MLflow champion

    
Intuition. The API shouldn't care which model is best; it asks the registry for "whoever is champion today". Promoting a challenger then becomes a registry change, not a code change.

    
In the registry, the alias @champion points at one model version. The URI models:/churn-classifier@champion always means "the version the champion alias points at right now". (See the MLOps pipeline page for how challengers are evaluated and promoted.)

    
Register a model and set the alias


# register_model.py  (tested with MLflow 3.17)
import mlflow
import numpy as np
import pandas as pd
from mlflow import MlflowClient
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

mlflow.set_tracking_uri("sqlite:///mlflow.db")
mlflow.set_experiment("churn")
MODEL_NAME = "churn-classifier"

rng = np.random.default_rng(42)
X = pd.DataFrame({
    "tenure_months": rng.integers(0, 72, 500).astype(float),
    "monthly_charges": rng.uniform(20, 120, 500),
    "support_calls": rng.integers(0, 10, 500).astype(float),
})
y = ((X.support_calls > 4) | (X.tenure_months < 6)).astype(int)
model = make_pipeline(StandardScaler(), LogisticRegression()).fit(X, y)

with mlflow.start_run():
    info = mlflow.sklearn.log_model(
        model,
        name="model",
        input_example=X.head(3),
        pyfunc_predict_fn="predict_proba",      # pyfunc .predict() returns probabilities
        registered_model_name=MODEL_NAME,
    )

client = MlflowClient()
version = info.registered_model_version
client.set_registered_model_alias(MODEL_NAME, "champion", version)
print(f"{MODEL_NAME} v{version} is now @champion")

    
Observed output on the first and second runs: Created version '1' of model 'churn-classifier'. … churn-classifier v1 is now @champion, then v2 is now @champion. pyfunc_predict_fn="predict_proba" matters: by default a scikit-learn model loaded through mlflow.pyfunc returns class labels (0/1), not probabilities.


    
Load the champion at startup


# serve.py
import logging
import os
from contextlib import asynccontextmanager

import mlflow
import pandas as pd
from fastapi import FastAPI, HTTPException, Response
from mlflow import MlflowClient
from pydantic import BaseModel, Field

logger = logging.getLogger("churn-api")
MODEL_NAME = os.getenv("MODEL_NAME", "churn-classifier")
MODEL_ALIAS = os.getenv("MODEL_ALIAS", "champion")
mlflow.set_tracking_uri(os.getenv("MLFLOW_TRACKING_URI", "sqlite:///mlflow.db"))

state: dict = {"model": None, "version": None}


def load_champion() -> None:
    """Load models:/<name>@champion and remember which version it is."""
    client = MlflowClient()
    mv = client.get_model_version_by_alias(MODEL_NAME, MODEL_ALIAS)
    model = mlflow.pyfunc.load_model(f"models:/{MODEL_NAME}@{MODEL_ALIAS}")
    state["model"], state["version"] = model, str(mv.version)   # swap in one step
    logger.info("Loaded %s version %s", MODEL_NAME, mv.version)


@asynccontextmanager
async def lifespan(app: FastAPI):
    try:
        load_champion()                    # once, at startup - never per request
    except Exception:
        logger.exception("Could not load the champion model")
    yield


app = FastAPI(title="Churn API", version="1.0.0", lifespan=lifespan)


class ChurnRequest(BaseModel):
    tenure_months: int = Field(ge=0, le=120)
    monthly_charges: float = Field(gt=0, le=1000)
    support_calls: int = Field(ge=0, le=50)


class ChurnResponse(BaseModel):
    churn_probability: float
    will_churn: bool
    model_version: str


@app.get("/health")
def health(response: Response) -> dict:
    loaded = state["model"] is not None
    if not loaded:
        response.status_code = 503
    return {"status": "ok" if loaded else "unavailable", "model_loaded": loaded,
            "model_name": MODEL_NAME, "model_version": state["version"]}


@app.post("/v1/process", response_model=ChurnResponse)
def process(req: ChurnRequest) -> ChurnResponse:
    if state["model"] is None:
        raise HTTPException(status_code=503, detail="Model not loaded")
    X = pd.DataFrame([req.model_dump()]).astype(float)   # same columns as training
    try:
        proba = float(state["model"].predict(X)[0][1])
    except Exception:
        logger.exception("Prediction failed")
        raise HTTPException(status_code=500, detail="Internal server error")
    return ChurnResponse(churn_probability=round(proba, 4), will_churn=proba >= 0.5,
                         model_version=str(state["version"]))


@app.post("/admin/reload-model")
def reload_model() -> dict:
    """Call this after moving the @champion alias (protect it with auth in real life)."""
    try:
        load_champion()
    except Exception:
        logger.exception("Reload failed; keeping the old model")
        raise HTTPException(status_code=503, detail="Reload failed; previous model still serving")
    return {"reloaded": True, "model_version": state["version"]}

Why report the version?
When a prediction looks odd, the first question is "which model made it?". Returning model_version in /health and in each response lets you trace any prediction back to its MLflow run, data and metrics.

      
Never load per request
Loading a model means reading files, unpickling and maybe downloading artefacts: tens of milliseconds to many seconds. Doing it inside process() would make every request slow and hammer the registry. Load once; reuse the object in memory.

    

    
When the alias moves: reloading

    
The server loaded the champion at startup. If you promote a new version, the running server keeps using the old one until told otherwise. Simple options, from simplest up:

    
    
      
  1. Restart or redeploy the service. The new process loads the new champion. Simple and very common, especially with containers.
    2. 
      
  2. A reload endpoint like /admin/reload-model above, called by your promotion pipeline after it moves the alias. Protect it with authentication. Notice it loads the new model first and only swaps it in if loading succeeded; on failure the old model keeps serving.
    3. 
      
  3. Poll the registry: a background task checks get_model_version_by_alias every few minutes and calls load_champion() when the version number changes.
    4. 
    

    
Environment variables, not hard-coded values: the tracking URI, model name and alias come from os.getenv, so the same code can point at a local sqlite:///mlflow.db in development and at a shared MLflow server in production. Never hard-code credentials.

    
MLflow also has a built-in server, mlflow models serve -m "models:/churn-classifier@champion" --port 5001, which exposes a generic /invocations endpoint. It's handy for quick tests, but writing your own FastAPI app gives you your own input schema, business rules, error messages and health checks.

15Production notes

    
Intuition. On your laptop the API serves one person. In production it serves many callers, over the internet, all day: it needs more workers, encryption, a lock on the door and a paper trail.

    

      
ConcernWhat to do

      
        
Multiple workersuvicorn main:app --host 0.0.0.0 --port 8000 --workers 4 (or fastapi run main.py --workers 4) runs 4 processes, so requests are served in parallel. Each worker loads its own copy of the model, so memory use multiplies. In Kubernetes or ECS you often run one worker per container and scale the number of containers instead.

        
Reverse proxyPut a proxy or load balancer (nginx, Traefik, an AWS Application Load Balancer) in front. It receives traffic on 80/443, forwards it to your app's port, spreads load across copies, and uses /health to stop sending traffic to unhealthy ones. This is where 502 and 504 come from.

        
HTTPSAnything leaving your machine must use https. Usually the proxy handles the certificates (this is called TLS termination) and talks plain HTTP to the app on the private network.

        
AuthenticationAt minimum an API key in a header, checked with a dependency; 401 if missing or wrong. Keys come from environment variables or a secrets manager, never the code. Example below.

        
Logging with request IDsLog method, path, status code, latency, model version and a request ID for every call. Return the ID in an X-Request-ID header so callers can quote it. Don't log raw personal data.

        
CORSBrowsers block JavaScript on one site from calling an API on another origin unless the API allows it: app.add_middleware(CORSMiddleware, allow_origins=["https://dashboard.example.com"]). (Not needed for Streamlit, which calls the API from its Python server, not from the browser.)

        
DockerCMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]: inside a container, bind to 0.0.0.0 or nothing outside can reach it.

        
Rate limiting, input sizeCap request rates (429) and body sizes at the proxy so one caller can't overwhelm the service.

      
    

    
An API key check and a request-ID middleware, both tested (missing or wrong key → 401 {"detail":"Invalid or missing API key"}; correct key → 200 with the X-Request-ID echoed back):


import logging
import os
import secrets
import uuid

from fastapi import Depends, FastAPI, HTTPException, Request, Security
from fastapi.middleware.cors import CORSMiddleware
from fastapi.security import APIKeyHeader

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger("churn-api")
app = FastAPI()

api_key_header = APIKeyHeader(name="X-API-Key", auto_error=False)


def require_api_key(key: str | None = Security(api_key_header)) -> None:
    expected = os.environ["API_KEY"]                  # never hard-code secrets
    if key is None or not secrets.compare_digest(key, expected):
        raise HTTPException(status_code=401, detail="Invalid or missing API key")


@app.middleware("http")
async def add_request_id(request: Request, call_next):
    request_id = request.headers.get("X-Request-ID") or str(uuid.uuid4())
    response = await call_next(request)
    response.headers["X-Request-ID"] = request_id
    logger.info("%s %s -> %s id=%s", request.method, request.url.path,
                response.status_code, request_id)
    return response


app.add_middleware(CORSMiddleware, allow_origins=["https://dashboard.example.com"],
                   allow_methods=["GET", "POST"], allow_headers=["*"])


@app.post("/v1/process", dependencies=[Depends(require_api_key)])
def process() -> dict:
    return {"ok": True}

    
secrets.compare_digest compares strings in constant time, so an attacker can't guess the key character by character from response timings.
