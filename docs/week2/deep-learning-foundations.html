Deep learning foundations: from one neuron to a trained network

How a neural network turns inputs into a prediction, how it measures its own mistakes, and how backpropagation and gradient descent use those mistakes to improve the weights. Along the way: activation functions, loss functions, optimisers, the learning rate, regularisation, and complete training code in Keras and PyTorch.

1Machine learning vs deep learning

Intuition. In classic machine learning, you design the features and the model learns how to weigh them. In deep learning, the network learns the features as well, layer by layer, straight from raw data such as pixels, audio or text.

Deep learning is the part of machine learning that uses neural networks with several layers. Each layer transforms its input a little, and stacking many layers lets the network build up complex patterns from simple ones. In an image model, early layers detect edges, middle layers detect shapes such as eyes or wheels, and late layers detect whole objects.

Classic ML (trees, boosting, linear models)Deep learning (neural networks)
FeaturesMostly hand-engineered by youLearned automatically from raw data
Best data typeTabular (rows and columns)Unstructured: images, audio, text, video
Data neededWorks with hundreds to thousands of rowsUsually tens of thousands or more (less with transfer learning)
ComputeA laptop CPU is usually enoughOften needs a GPU (graphics card) for training
Tuning effortModerate; good defaultsHigher: architecture, learning rate, regularisation…
InterpretabilityOften good (coefficients, feature importance, SHAP)Harder; a "black box" without extra tools

When is deep learning worth it?

Reach for deep learning when

  • The data is unstructured: images, sound, free text, video, sequences
  • You have a lot of data, or a pre-trained model you can fine-tune (transfer learning)
  • The patterns are very complex and hard to describe as features
  • You need to combine data types (image + text) or generate content

Think twice when

  • The data is a modest-sized table: gradient boosting (XGBoost, LightGBM, CatBoost) often matches or beats neural networks there, with less tuning
  • You need to explain each prediction to a regulator or a customer
  • You have little data and no suitable pre-trained model
  • Training time, cost or hardware are tight

Be balanced, not tribal. On tabular data, start with a gradient-boosting baseline (Week 1). A neural network can still be useful there: with very large datasets, many high-cardinality categories (via embeddings, learned vector representations of categories), or when the table is one input to a bigger model. Compare both with the same validation set and the same metric, and let the numbers decide.

2The artificial neuron

Intuition. A neuron is a tiny decision-maker: it multiplies each input by how important it thinks that input is (a weight), adds them up with a starting offset (the bias), and passes the total through a simple function (the activation) that decides how strongly it "fires".

Inputs

→
× weights

→
Sum + bias
z = Σ wᵢxᵢ + b
→
Activation
a = f(z)
→
Output a
  • Inputs (x): the numbers going in. For the first layer these are your features; for later layers they are the outputs of the previous layer.
  • Weights (w): one per input. A large positive weight means "this input pushes me up strongly"; a negative weight means "this input pushes me down". Weights are learned during training.
  • Bias (b): a learned offset. It shifts the neuron's threshold, so it can fire even when all inputs are zero, or stay quiet unless the inputs are large.
  • Weighted sum (z, also called the pre-activation or logit): z = w₁x₁ + w₂x₂ + … + wₙxₙ + b.
  • Activation function (f): a fixed function applied to z. Its output a = f(z) is what the neuron passes on.

If this looks familiar, it should: a single neuron with a sigmoid activation is logistic regression. A single neuron with no activation (a "linear" one) is linear regression. Neural networks get their power from connecting many of these together.

Worked example. Inputs x = (2, 3), weights w = (0.5, −1.0), bias b = 1.5.

z = 0.5 × 2 + (−1.0) × 3 + 1.5 = 1 − 3 + 1.5 = −0.5

With ReLU: a = max(0, −0.5) = 0 (the neuron is "off"). With sigmoid: a = 1 / (1 + e0.5) = 0.378.

3Activation functions

Intuition. Activations add the "bend". Without them, stacking layers is pointless: a chain of weighted sums is still just one weighted sum, a straight line. A non-linear activation in each hidden layer is what lets a network learn curves, interactions and complex shapes.

Why it matters: if every layer were linear, then layer2(layer1(x)) = W₂(W₁x + b₁) + b₂ = (W₂W₁)x + (W₂b₁ + b₂), which is a single linear layer. A 50-layer linear network can do nothing that logistic regression can't.

In softmax's derivative, δᵢⱼ is 1 when i = j and 0 otherwise. You will rarely need it by hand, because softmax is almost always paired with cross-entropy, and that pair has a beautifully simple combined gradient (see Backpropagation).

The vanishing gradient problem, in one paragraph

Backpropagation multiplies the slopes of every layer together. Sigmoid's slope is at most 0.25, and close to 0 when |z| is large (the flat, "saturated" ends of the S-curve). Through 10 sigmoid layers the gradient can shrink by a factor of up to 0.2510 ≈ 0.000001, so the early layers barely learn. ReLU's slope is exactly 1 for positive inputs, so gradients pass through unchanged. This is the main reason ReLU replaced sigmoid in hidden layers. More in section 13.

The "dying ReLU". If a ReLU neuron's z is negative for every training example, its output and its gradient are both 0, so its weights never update again. A too-high learning rate makes this more likely. Leaky ReLU keeps a small slope (α) for negative z, so the neuron can recover.

Rule of thumb: ReLU in the hidden layers; choose the output activation from the task (sigmoid, softmax or linear). That covers most feed-forward networks.

4Layers and network shape

Intuition. Neurons are organised in layers. Every neuron in one layer feeds every neuron in the next. The first layer receives the data, the last layer gives the answer, and the layers in between ("hidden" because you never see their values directly) build up the useful features.

LayerWhat it isHow many neurons?
Input layerNot really neurons: it just holds the feature values of one example. No weights, no activationOne per feature (after encoding). 12 columns → 12 inputs
Hidden layer(s)Weighted sum + activation (usually ReLU). Learn intermediate featuresYour choice: 16–512 is typical for tabular data; often powers of two
Output layerWeighted sum + task-specific activationSet by the task: 1 for binary or regression, K for K classes

MLP vs "deep" neural network

  • A dense (or fully connected) layer connects every input to every neuron. In Keras it's Dense; in PyTorch it's nn.Linear (plus a separate activation).
  • A multilayer perceptron (MLP), also called a feed-forward network, is a stack of dense layers where data flows one way, input to output. It's the right network for tabular data and the foundation for everything else.
  • A deep neural network (DNN) simply has several hidden layers. There's no strict cut-off; "two or more hidden layers" is a common informal definition. In practice, "deep learning" usually means many layers and often specialised layer types: convolutional layers for images, recurrent layers and transformers for sequences. See Neural network architectures.

Counting parameters

A dense layer with n_in inputs and n_out neurons has n_in × n_out weights plus n_out biases. These are the parameters the network learns.

Example: 10 features → Dense(64) → Dense(32) → Dense(1).

10 × 64 + 64 = 704 · 64 × 32 + 32 = 2,080 · 32 × 1 + 1 = 33 · total = 2,817 parameters. Keras' model.summary() prints exactly this.

Wider (more neurons per layer) and deeper (more layers) both add capacity, meaning the network can fit more complex patterns, and also overfit more easily. For tabular data, 2–3 hidden layers is usually plenty.

Logits and from_logits. For numerical stability, many people leave the output layer linear and let the loss apply sigmoid or softmax internally. Applying softmax twice is a classic silent bug.

Softmax in action

Softmax turns any list of scores into probabilities: exponentiate each one (so all are positive), then divide by the total (so they sum to 1). Bigger scores get disproportionately more probability.

6The forward pass

Intuition. The forward pass is just "run the network": push the inputs through each layer in turn, computing weighted sums and activations, until a prediction comes out of the end. No learning happens here; it is pure arithmetic.

A fully worked example

A tiny network: 2 inputs → 2 hidden neurons (ReLU) → 1 output neuron (sigmoid), for binary classification. One training example: x₁ = 1.0, x₂ = 2.0, true label y = 1.

NeuronWeight from x₁ / h₁Weight from x₂ / h₂Bias
Hidden h₁w₁₁ = 0.5w₂₁ = −0.2b₁ = 0.1
Hidden h₂w₁₂ = 0.3w₂₂ = 0.4b₂ = −0.5
Output ov₁ = 0.8v₂ = −0.5c = 0.5

Step 1: hidden layer

z₁ = 0.5 × 1.0 + (−0.2) × 2.0 + 0.1 = 0.5 − 0.4 + 0.1 = 0.2 → a₁ = ReLU(0.2) = 0.2

z₂ = 0.3 × 1.0 + 0.4 × 2.0 + (−0.5) = 0.3 + 0.8 − 0.5 = 0.6 → a₂ = ReLU(0.6) = 0.6

Step 2: output layer

zo = 0.8 × 0.2 + (−0.5) × 0.6 + 0.5 = 0.16 − 0.30 + 0.5 = 0.36

ŷ = sigmoid(0.36) = 1 / (1 + e−0.36) = 1 / (1 + 0.6977) = 0.589

Step 3: loss

The true label is 1, so binary cross-entropy is L = −ln(ŷ) = −ln(0.589) = 0.529. The model leans the right way (0.589 > 0.5) but isn't confident, so the loss is moderate. A perfect prediction (ŷ = 1) would give L = 0.

In matrix form, a whole layer for a whole batch of examples is one line: A = f(XW + b), where X is (batch × inputs), W is (inputs × neurons) and b is added to every row. This is why GPUs, which are very fast at matrix multiplication, speed deep learning up so much.

7Loss functions

Intuition. The loss is a single number that says "how wrong was that?". Training means turning the weights to make this number as small as possible on the training data.

The loss is computed per example and averaged over a batch. (Some texts say cost for the average; they mean the same thing in practice.) It must be differentiable, meaning smooth enough that we can compute its slope with respect to every weight, because that slope is what training follows. That's why we train on cross-entropy rather than directly on accuracy: accuracy only changes in jumps.

LossFormula (one example)Use forNotes
Binary cross-entropy (log loss)−[y·ln(ŷ) + (1 − y)·ln(1 − ŷ)]Binary and multi-label classificationPunishes confident wrong answers very heavily
Categorical cross-entropy−Σₖ yₖ·ln(ŷₖ) = −ln(probability of the true class)Multi-classOnly the true class's probability matters
Mean squared error (MSE)(y − ŷ)²RegressionSquares big errors, so sensitive to outliers
Mean absolute error (MAE)|y − ŷ|Regression with outliersTreats all errors linearly; more robust
HuberMSE for small errors, MAE for large onesRegressionA compromise between the two

Why cross-entropy punishes confident mistakes

True yPredicted ŷBinary cross-entropy
10.9 (confident, right)−ln(0.9) = 0.105
10.5 (unsure)−ln(0.5) = 0.693
10.1 (confident, wrong)−ln(0.1) = 2.303
10.01 (very confident, wrong)−ln(0.01) = 4.605

A useful sanity check: for a balanced binary problem, an untrained network predicting about 0.5 everywhere starts at a loss near 0.693 (= ln 2). For K balanced classes it starts near ln K (2.303 for 10 classes). If your first-epoch loss is far above that, something is wrong with the data or the set-up.

8Backpropagation

Intuition. After a wrong prediction, backpropagation works out how much each weight is to blame. It starts at the loss and walks backwards through the network, layer by layer, handing out each weight's share of the blame. That share is the weight's gradient.

Gradients and the chain rule

  • A gradient ∂L/∂w ("the partial derivative of the loss with respect to w") answers: if I nudge this weight up a tiny bit, how much does the loss change? Positive means increasing w increases the loss, so we should decrease w. Negative means the opposite. The size says how sensitive the loss is to that weight.
  • The network is a chain of simple steps: weight → z → activation → next z → … → loss. The chain rule from calculus says the effect of a change at the start of the chain is the product of the effects of each link: ∂L/∂w = ∂L/∂a · ∂a/∂z · ∂z/∂w.
  • Backpropagation computes these products efficiently by starting at the end and reusing each layer's result for the layer before it. One backward pass gives the gradient for every weight, at roughly the cost of one or two forward passes.
Forward →
inputs → prediction → loss
← Backward
loss → output layer → hidden layers
Update
w ← w − η · ∂L/∂w

One worked gradient: the output weight v₁

Continue the example from section 6: ŷ = 0.589, y = 1, a₁ = 0.2. How should v₁ (the weight from h₁ to the output, currently 0.8) change?

By the chain rule: ∂L/∂v₁ = ∂L/∂ŷ · ∂ŷ/∂zo · ∂zo/∂v₁

  • ∂L/∂ŷ = −y/ŷ + (1 − y)/(1 − ŷ) (derivative of binary cross-entropy)
  • ∂ŷ/∂zo = ŷ(1 − ŷ) (derivative of sigmoid)
  • Multiply those two and simplify: ∂L/∂zo = ŷ − y. Sigmoid + cross-entropy collapses to "prediction minus truth". (Softmax + categorical cross-entropy gives the same neat result: ŷₖ − yₖ for each class.)
  • ∂zo/∂v₁ = a₁, because zo = v₁a₁ + v₂a₂ + c.

So ∂L/∂v₁ = (ŷ − y) · a₁ = (0.589 − 1) × 0.2 = −0.411 × 0.2 = −0.0822

The gradient is negative, so increasing v₁ lowers the loss. With a learning rate η = 0.1: v₁ ← 0.8 − 0.1 × (−0.0822) = 0.8082. Re-running the forward pass with this new v₁ (and nothing else changed) lowers the loss from 0.5293 to 0.5286. A tiny step, as it should be; training repeats this thousands of times.

Reading the blame. The gradient is error × the input that weight saw. For v₂ it's −0.411 × 0.6 = −0.247: three times larger, because h₂ was three times more active, so v₂ had more influence on the mistake. And if a hidden neuron outputs 0 (an "off" ReLU), its outgoing weights get zero gradient for that example: no influence, no blame.

One layer further back. For the hidden weight w₁₁: ∂L/∂w₁₁ = (ŷ − y) · v₁ · ReLU′(z₁) · x₁ = −0.411 × 0.8 × 1 × 1.0 = −0.329. Each extra layer multiplies in one more weight and one more activation slope, which is exactly why small slopes (sigmoid) make gradients vanish in deep networks.

You never code this by hand. Keras (via TensorFlow, JAX or PyTorch) and PyTorch use automatic differentiation: they record the forward pass and compute all gradients for you. In PyTorch it's literally loss.backward(). Understanding it still matters for debugging vanishing gradients, dead neurons and exploding losses.

9Gradient descent and the learning rate

Intuition. Imagine standing on a foggy hillside, trying to reach the valley floor. You can't see far, but you can feel the slope under your feet. So you take a step downhill, feel again, and repeat. The gradient is the slope; the learning rate is the size of your step.

The update rule, applied to every weight after each batch:

w ← w − η · ∂L/∂w
  • ∂L/∂w points uphill (the direction that increases the loss), so we subtract it.
  • η (eta) is the learning rate: how big a step to take. It's the single most important hyperparameter in deep learning.
  • The loss surface (or loss landscape) is the loss plotted against all the weights. Real networks have millions of dimensions; the widget below uses 2 so you can see it.

The learning rate: too small, too large, just right

Just rightBig enough to make progress, small enough not to overshootLoss drops quickly, then flattens out
Too largeOvershoots the valley floor and bounces from side to sideLoss is jumpy, zig-zags, or plateaus high
Far too largeEach bounce lands higher than the lastLoss explodes; NaN (not a number) appears

A long, narrow valley: the loss is L = 0.1·w₁² + w₂², steep across (w₂) and shallow along (w₁). The minimum is at the cross. Choose a learning rate and an optimiser, then press Step or Run 50 steps. Changing either setting restarts from the same point.

Things to try: SGD at 0.001 (too slow), 0.3 (converges cleanly), 0.9 (zig-zags across the valley) and 1.1 (diverges, because each step overshoots by more than it corrects). Then switch to momentum and Adam at 0.01 and 0.1. Note that on this simple bowl Adam copes with large rates, because each Adam step is capped at roughly η per weight; in real networks a too-high Adam learning rate still makes training unstable.

10Batches, epochs and iterations

Intuition. You don't need to look at every training example before taking a step. Estimating the slope from a small random handful (a mini-batch) is much faster and nearly as good, and the bit of noise even helps.

VariantExamples per updateProsCons
Batch gradient descentAll of themExact gradient; smooth pathOne update per pass over the data; doesn't fit in memory for big data
Stochastic gradient descent (SGD, strictly)1Very frequent updates; noise can escape poor regionsVery noisy; can't use the GPU's parallelism
Mini-batch gradient descentA small batch, e.g. 32–256Best of both: fast, GPU-friendly, mildly noisyOne more hyperparameter (batch size)

In practice everyone uses mini-batches, and frameworks still call the optimiser "SGD". When people say "SGD" they almost always mean mini-batch gradient descent.

Vocabulary

  • Batch size: examples used to compute one gradient update. Keras' default is 32.
  • Iteration (or step): one update of the weights = one batch.
  • Epoch: one full pass through the whole training set. The data is usually reshuffled every epoch.
  • Iterations per epoch = ⌈training examples ÷ batch size⌉ (rounded up; the last batch is smaller).

Example: 10,000 training rows, batch size 32 → 10,000 ÷ 32 = 312.5 → 313 iterations per epoch. Training for 20 epochs = 313 × 20 = 6,260 weight updates.

Batch-size trade-offs: larger batches give smoother gradients and use the GPU better, but need more memory and often generalise slightly worse; smaller batches are noisier, which acts as mild regularisation. If you change the batch size a lot, you often need to retune the learning rate too (larger batches tolerate larger learning rates).

11Optimisers

Intuition. Plain gradient descent only looks at the slope right now. Better optimisers also remember where they've been heading (momentum) and adjust the step size for each weight separately (adaptive rates), like a hiker who builds up speed on long slopes and takes shorter steps on rough ground.

Notation: g is the current gradient ∂L/∂w, η the learning rate, and all operations are per weight.

  • ε (epsilon) is a tiny number that prevents division by zero. Keras uses 1e-7; PyTorch uses 1e-8.
  • PyTorch's torch.optim.Adam has the same defaults: lr=1e-3, betas=(0.9, 0.999). For torch.optim.SGD, always set lr (and usually momentum=0.9) yourself.

Which to pick? Start with Adam at 0.001: it works well with little tuning on most problems. Well-tuned SGD with momentum (plus a learning-rate schedule) sometimes generalises slightly better on image models, at the cost of more tuning. Use AdamW for transformers.

Learning-rate schedules and warm-up

The best learning rate changes during training: large steps help early, when you're far from a good solution, and small steps help late, when you're fine-tuning near one. A schedule changes η automatically. Common ones: step decay (multiply by 0.1 every N epochs), exponential decay, cosine decay (a smooth curve down to near zero), and reduce-on-plateau (cut η when the validation loss stops improving; Keras ReduceLROnPlateau). Warm-up starts with a tiny learning rate and ramps it up over the first few hundred or thousand steps; it stops the very first, noisy updates from wrecking a randomly initialised network, and is standard for transformers and large batch sizes.

# Keras: cosine decay, set on the optimiser
schedule = keras.optimizers.schedules.CosineDecay(initial_learning_rate=1e-3, decay_steps=10_000)
optimizer = keras.optimizers.Adam(learning_rate=schedule)

# Keras: halve the learning rate when val_loss stalls for 5 epochs
reduce_lr = keras.callbacks.ReduceLROnPlateau(monitor="val_loss", factor=0.5, patience=5)

# PyTorch
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=100)   # call scheduler.step() each epoch

12Weight initialisation

Intuition. Training starts from random weights, and the scale of that randomness matters. Too big and signals explode as they pass through layers; too small and they fade to nothing. Good initialisation keeps the signal at roughly the same size in every layer.

  • Never initialise all weights to zero (or to the same value). Every neuron in a layer would compute the same thing and receive the same gradient, so they'd stay identical forever. Random initialisation breaks the symmetry. Biases can safely start at 0.
  • Glorot / Xavier initialisation scales the random weights by the number of inputs and outputs of the layer. Good for tanh and sigmoid. It's Keras' default for Dense (glorot_uniform).
  • He / Kaiming initialisation uses a variance of 2 ÷ (number of inputs), which compensates for ReLU zeroing out half its inputs. The usual recommendation for ReLU networks: Dense(64, activation="relu", kernel_initializer="he_normal"). PyTorch's nn.Linear default is a Kaiming-style uniform scaled by the number of inputs.

For shallow MLPs the defaults are fine. Initialisation matters more as networks get deeper, and in practice it's combined with batch normalisation and residual connections.

13Vanishing and exploding gradients, and input scaling

Intuition. The gradient for an early layer is a long product of numbers, one per later layer. Multiply many numbers below 1 and you get almost 0 (vanishing). Multiply many above 1 and you get a huge number (exploding). Either way, training breaks.

Vanishing gradients

Symptoms: loss stalls early; the first layers' weights barely change; very deep networks train worse than shallow ones.

Fixes: ReLU-family activations instead of sigmoid/tanh in hidden layers · He initialisation · batch normalisation · residual (skip) connections · LSTM/GRU instead of plain RNNs for sequences.

Exploding gradients

Symptoms: loss jumps wildly or becomes NaN; weights grow enormous. Common in recurrent networks.

Fixes: a lower learning rate · gradient clipping (cap the gradient's size: Adam(clipnorm=1.0) in Keras, torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0) in PyTorch) · good initialisation · batch normalisation.

Scale your inputs

Neural networks are very sensitive to the scale of their inputs. If one feature is "salary" (tens of thousands) and another is "age" (tens), the salary weights get gradients thousands of times larger, so a single learning rate can't suit both, and sigmoid/tanh neurons saturate. Standardise numeric features to mean 0 and standard deviation 1 (StandardScaler), or squash them into [0, 1] (MinMaxScaler; for images, divide pixel values by 255).

Fit the scaler on the training data only, then apply it to validation and test data. Fitting it on everything leaks information from the test set, exactly as in Week 1. Keras also offers a layers.Normalization() layer that you adapt() to the training data, so the scaling travels with the saved model.

Categorical features need encoding first: one-hot encoding for a few categories, or an Embedding layer for many.

14Overfitting and regularisation

Intuition. A neural network has so many weights that it can simply memorise the training set, noise and all. Regularisation techniques make memorising harder or stop training before it happens, so the network is pushed to learn patterns that generalise.

The diagnosis is the same as in Week 1: training loss keeps falling while validation loss starts rising. The fixes are mostly specific to neural networks:

Train mode vs evaluation mode. Dropout and batch normalisation behave differently in training and prediction. Keras switches automatically (fit vs predict/evaluate). In PyTorch you must call model.train() before training and model.eval() before validating or predicting. Forgetting model.eval() gives noisy, worse predictions.

Note that EarlyStopping's restore_best_weights defaults to False: without it you keep the weights from the last epoch, which are patience epochs past the best.

15A complete example: tabular binary classification

Intuition. Every training script follows the same recipe: split, scale, define the network, choose loss and optimiser, train with validation and early stopping, then evaluate once on the test set.

The task: predict customer churn (1) or not (0) from numeric features in X (a NumPy array or DataFrame of numbers) and labels y.

Keras

import numpy as np
import keras
from keras import layers
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler

# 1. Split first (stratified keeps the churn rate the same in both sets), then scale
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42)
scaler = StandardScaler().fit(X_train)          # fit on training data only
X_train = scaler.transform(X_train)
X_test = scaler.transform(X_test)

# 2. Define the network
keras.utils.set_random_seed(42)                 # reproducible weights and dropout
model = keras.Sequential([
    keras.Input(shape=(X_train.shape[1],)),     # one input per feature
    layers.Dense(64, activation="relu"),
    layers.Dropout(0.3),
    layers.Dense(32, activation="relu"),
    layers.Dropout(0.3),
    layers.Dense(1, activation="sigmoid"),      # binary: 1 unit + sigmoid
])
model.summary()                                 # layers and parameter counts

# 3. Choose the loss, optimiser and metrics
model.compile(
    optimizer=keras.optimizers.Adam(learning_rate=1e-3),
    loss="binary_crossentropy",
    metrics=["accuracy", keras.metrics.AUC(name="auc")],
)

# 4. Train with a validation split and early stopping
early_stop = keras.callbacks.EarlyStopping(
    monitor="val_loss", patience=10, restore_best_weights=True)
history = model.fit(
    X_train, y_train,
    validation_split=0.2,     # last 20% of the training rows become validation data
    epochs=200,               # an upper limit; early stopping decides the real number
    batch_size=32,
    callbacks=[early_stop],
    verbose=0,
)

# 5. Evaluate once on the untouched test set
test_loss, test_acc, test_auc = model.evaluate(X_test, y_test, verbose=0)
print(f"test loss {test_loss:.3f} · accuracy {test_acc:.3f} · ROC-AUC {test_auc:.3f}")
proba = model.predict(X_test).ravel()           # probabilities of churn
y_pred = (proba >= 0.5).astype(int)              # choose the threshold for the business

validation_split takes the last fraction of the rows, before any shuffling. That's fine here because train_test_split already shuffled the data. If your data is sorted (by date or by class), shuffle it first, or pass an explicit validation_data=(X_val, y_val). For imbalanced classes, add class_weight={0: 1.0, 1: 5.0} to fit.

The history.history dictionary holds the per-epoch loss, val_loss, accuracy, val_accuracy and so on, ready to plot (see section 16) or to log with MLflow.

The same thing in PyTorch

PyTorch has no fit(): you write the training loop yourself. It's more code but shows every step of sections 6–11 explicitly.

import torch
from torch import nn
from torch.utils.data import TensorDataset, DataLoader

torch.manual_seed(42)
# Reuse the scaled X_train / X_test from above; carve out a validation set
X_tr, X_val, y_tr, y_val = train_test_split(X_train, y_train, test_size=0.2,
                                            stratify=y_train, random_state=42)
to_t = lambda a: torch.tensor(np.asarray(a), dtype=torch.float32)
X_tr, X_val, X_te = to_t(X_tr), to_t(X_val), to_t(X_test)
y_tr, y_val = to_t(y_tr).unsqueeze(1), to_t(y_val).unsqueeze(1)   # shape (n, 1)

model = nn.Sequential(
    nn.Linear(X_tr.shape[1], 64), nn.ReLU(), nn.Dropout(0.3),
    nn.Linear(64, 32), nn.ReLU(), nn.Dropout(0.3),
    nn.Linear(32, 1),                 # no sigmoid: the loss below applies it (logits)
)
loss_fn = nn.BCEWithLogitsLoss()      # sigmoid + binary cross-entropy, numerically stable
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)
train_dl = DataLoader(TensorDataset(X_tr, y_tr), batch_size=32, shuffle=True)

best_val, patience, wait = float("inf"), 10, 0
for epoch in range(200):
    model.train()                     # dropout ON
    for xb, yb in train_dl:           # one iteration per mini-batch
        optimizer.zero_grad()         # clear the previous step's gradients
        loss = loss_fn(model(xb), yb) # forward pass + loss
        loss.backward()               # backpropagation: compute all gradients
        optimizer.step()              # gradient descent update (Adam)

    model.eval()                      # dropout OFF
    with torch.no_grad():             # no gradients needed for validation
        val_loss = loss_fn(model(X_val), y_val).item()
    if val_loss < best_val - 1e-4:    # early stopping, by hand
        best_val, wait = val_loss, 0
        best_state = {k: v.clone() for k, v in model.state_dict().items()}
    else:
        wait += 1
        if wait >= patience:
            break

model.load_state_dict(best_state)     # restore the best weights
model.eval()
with torch.no_grad():
    proba = torch.sigmoid(model(X_te)).squeeze(1).numpy()

18Cheat sheet

The core loop

  1. Forward: z = Wx + b, a = f(z), layer by layer → ŷ
  2. Loss: compare ŷ with y
  3. Backward: chain rule → ∂L/∂w for every weight
  4. Update: w ← w − η·∂L/∂w (or Adam's version)
  5. Repeat for every mini-batch, for many epochs

Output + loss pairs

  • Binary → 1 unit, sigmoid, binary cross-entropy
  • Multi-class → K units, softmax, (sparse) categorical cross-entropy
  • Multi-label → K units, sigmoid, binary cross-entropy
  • Regression → 1 unit, linear, MSE / MAE / Huber
  • PyTorch: linear output + BCEWithLogitsLoss / CrossEntropyLoss

Activations

  • Hidden layers: ReLU (Leaky ReLU if neurons die; GELU in transformers)
  • Sigmoid: (0, 1), slope ≤ 0.25 → vanishing gradients if stacked
  • Tanh: (−1, 1), zero-centred, used inside RNNs
  • Softmax: probabilities summing to 1

Good defaults

  • Scale inputs (fit on train only)
  • Adam, learning_rate=0.001, β₁ = 0.9, β₂ = 0.999
  • Batch size 32; 2 hidden layers of 64 → 32 units
  • Dropout 0.2–0.3; early stopping, patience 10, restore best weights
  • Seed everything for reproducibility

Loss explodes / NaN

  • Lower the learning rate (÷ 10)
  • Scale the inputs; check for NaN or infinite values in the data
  • Clip gradients; use a from_logits loss

Loss won't go down

  • Check the output activation and loss pairing
  • Check labels match the loss (integer vs one-hot)
  • Try to overfit 100 rows; raise the learning rate; add capacity
  • Sigmoid hidden layers? Switch to ReLU

Remember: on tabular data, always compare against a gradient-boosting baseline. Deep learning earns its keep on images, audio, text and very large datasets. Next: CNNs, RNNs and LSTMs.
