Week 2 · Deep Learning & MLflow

Tracking experiments and models with MLflow

This week you will train at least three deep learning models. MLflow records every run (its settings, scores, plots and the model itself) so you can compare them side by side, reproduce the best one, and hand it on. This page covers tracking, autologging, comparing and searching runs, logging models, and the model registry with its champion and challenger aliases, which come back in Week 3's MLOps pipeline.

1The problem MLflow solves

Intuition. MLflow is a lab notebook that fills itself in. Every time you train a model, it writes down what you tried and how well it worked, so you never have to ask "which notebook cell produced my best model?"

Picture a normal Tuesday afternoon. You have trained a Keras network on the Adult Census Income data a dozen times. You changed the learning rate, added a layer, tried dropout, went back to fewer layers. One of those runs scored 85.7% validation accuracy. Which one? You re-ran some cells, the output was overwritten, and your notes say "lr 0.001? maybe 2 layers".

This is the normal state of machine learning without tracking. The four problems it causes:

ProblemWithout trackingWith MLflow
Memory"Which settings gave the 85.7%?" Lost when the cell re-ran.Every run is stored with its settings and scores, forever.
ReproducibilityYou can't rebuild the best model because you don't know the exact settings, data version or code version.Parameters, tags (data version, git commit) and the saved model sit together in one run.
ComparisonCopying numbers into a spreadsheet by hand; mistakes creep in.A sortable, filterable table and charts of all runs; select several and compare.
Collaboration and hand-over"The model is in final_v3_REAL.keras on my laptop."A shared tracking server and a model registry with named versions, such as "the current champion".

Reproducibility means that someone else (or you, in a month) can get the same result from the same inputs. It needs four things recorded: the code version, the data version, the settings, and the random seed. MLflow gives you a place to put all four.

MLflow is open source, works with almost any library (Keras, TensorFlow, PyTorch, scikit-learn, XGBoost and many more), and runs perfectly well on your own laptop with no server or cloud account.

2What MLflow is: its components

Intuition. MLflow is a toolbox, not one tool. This week you mostly use Tracking (recording runs). Models and the Model Registry (saving and versioning models) matter most in Week 3.

Tracking

An API and web UI for logging and browsing runs: parameters, metrics, artifacts and tags. The core of this week.

Models

A standard way to save a model with everything needed to load it again: the files, the library ("flavour"), dependencies and an input/output signature. Any MLflow model can be loaded the same way through mlflow.pyfunc.

Model Registry

A central catalogue of named models, each with numbered versions and movable aliases such as champion and challenger. Used heavily in Week 3.

Projects (briefly)

A way to package code with an MLproject file so it can be re-run with mlflow run. Less common today; you won't need it on this course.

Recent MLflow releases also add features for generative AI applications: tracing of LLM and agent calls, prompt versioning and LLM evaluation. You will meet some of these ideas in the agentic AI weeks; this page focuses on classic model tracking.

Two kinds of storage sit behind MLflow. The tracking store (also called the backend store) holds the small things: parameters, metrics, tags and run information. The artifact store holds files, which can be large: images, the saved model. On your laptop both live in your project folder.

Per-step metrics

A step is a counter you attach to a metric value, usually the epoch number (one epoch is one full pass through the training data). Logging val_loss at steps 0, 1, 2… gives MLflow a whole curve, which the UI draws as a line chart. In the runs table, MLflow shows the last value logged for each metric.

Try it: parameter, metric, artifact or tag?
Decide where each item belongs. You get instant feedback.

4Install and open the UI

Intuition. One command installs MLflow into your project, another opens a web page that shows every run you have logged.

Install with uv

The course uses uv, a fast Python package and project manager. From your project folder:

uv add mlflow                     # adds MLflow to pyproject.toml and installs it
uv add tensorflow scikit-learn    # if you don't already have them
uv run python -c "import mlflow; print(mlflow.__version__)"   # check it works

Start the UI

uv run mlflow ui

Then open http://127.0.0.1:5000 in your browser. Leave that terminal running; stop it with Ctrl+C. Run the command from your project folder: the UI reads runs from the folder it was started in.

Where are my runs stored?

By default, MLflow stores runs locally in your project folder. Depending on your MLflow version, that is either an mlruns/ folder or a SQLite database file called mlflow.db (newer default setups), with artifacts in a folder next to it. You can choose explicitly with a tracking URI, the address MLflow sends runs to:

Tracking URIWhere runs goWhen to use
(not set)The default local store in the current folderGetting started on your laptop
sqlite:///mlflow.dbA SQLite database file in the current folderLocal work, including the Model Registry; reliable and fast
http://127.0.0.1:5000A running MLflow server (mlflow server)Sharing one store between several scripts, notebooks or people
 
import mlflow

mlflow.set_tracking_uri("sqlite:///mlflow.db")   # optional: pick the store explicitly
print(mlflow.get_tracking_uri())                  # see where runs are going

If you set a tracking URI in code, start the UI pointing at the same store, for example uv run mlflow ui --backend-store-uri sqlite:///mlflow.db. A mismatch here is the number one reason for "the UI shows no runs" (see Troubleshooting).

Keep the stores out of git. Add these lines to .gitignore before your first commit. They can grow to gigabytes and may contain data.

mlruns/
mlartifacts/
mlflow.db

5Manual logging

Intuition. Open a run, write things into it, close it. The with mlflow.start_run(): block opens and closes the run for you, even if your code crashes.

The minimal pattern

import mlflow

mlflow.set_experiment("california-housing-mlp")      # created if it doesn't exist

with mlflow.start_run(run_name="mlp-2x64-adam-lr1e-3"):
    # 1. Parameters: the settings you chose
    mlflow.log_param("learning_rate", 0.001)
    mlflow.log_params({"hidden_layers": 2, "units": 64, "batch_size": 128, "epochs": 30})

    # 2. Tags: labels about the run
    mlflow.set_tag("data_version", "california-housing-sklearn-1.5")
    mlflow.set_tag("model_family", "mlp")

    # ... train the model here ...

    # 3. Metrics: final scores
    mlflow.log_metric("test_rmse", 0.531)
    mlflow.log_metrics({"test_mae": 0.372, "test_r2": 0.787})

When the with block ends, the run is marked FINISHED. If an exception is raised inside it, the run is marked FAILED, which is useful when you look back.

Logging a metric per epoch

Pass step= so MLflow can draw a curve. With Keras you can read the values from the History object that fit returns:

with mlflow.start_run(run_name="mlp-2x64-adam-lr1e-3"):
    mlflow.log_params({"learning_rate": 0.001, "epochs": 30})
    history = model.fit(X_train, y_train, validation_split=0.2, epochs=30, verbose=0)

    for epoch, (loss, val_loss) in enumerate(zip(history.history["loss"],
                                                 history.history["val_loss"])):
        mlflow.log_metric("loss", loss, step=epoch)
        mlflow.log_metric("val_loss", val_loss, step=epoch)

For live logging during training, you could log from inside a Keras callback instead. In practice autologging does this for you.

The logging functions

Common error: logging the same parameter twice with different values in one run raises an exception. This often happens when you log "epochs" yourself and autolog logs it too with a different value. Fix: give your own parameters distinct names, or let autolog handle them.

Getting the run ID

with mlflow.start_run(run_name="baseline") as run:
    ...
print(run.info.run_id)            # e.g. "3f2a9c..."
# inside a run you can also use: mlflow.active_run().info.run_id

6Autologging

Intuition. One line before training, and MLflow watches your library: it records the settings, the score after every epoch, and the model, without you writing any log_* calls.

import mlflow

mlflow.set_experiment("fashion-mnist-cnn")
mlflow.autolog()                      # turn on every supported integration

with mlflow.start_run(run_name="cnn-2conv-adam-lr1e-3"):
    model.fit(X_train, y_train, validation_split=0.1, epochs=15, batch_size=128)

Call autolog before you train. If no run is open when fit starts, autolog opens one for you, but wrapping it in your own start_run lets you choose the run name and add extra parameters and tags.

Generic or flavour-specific?

A flavour is MLflow's name for a library integration (the "Keras flavour", the "scikit-learn flavour"). You can turn autologging on for everything, or just for one library:

mlflow.autolog()               # all supported libraries that are installed
mlflow.tensorflow.autolog()    # Keras on TensorFlow only
mlflow.keras.autolog()         # Keras 3 (available in recent MLflow versions)
mlflow.sklearn.autolog()       # scikit-learn only

Gotcha: with the generic mlflow.autolog(), the scikit-learn integration also watches your preprocessing. Fitting a StandardScaler or ColumnTransformer can create extra runs you didn't expect. If you only want the Keras runs, use the flavour-specific call, or do your preprocessing before switching autolog on.

What autolog captures

The exact names vary a little between versions, so look at one run in the UI to see what yours records.

Keras / TensorFlowscikit-learn
ParametersTraining settings from fit (epochs, batch size), the optimiser's name and configuration (including the learning rate), early-stopping settings if you use that callbackEverything from estimator.get_params(), e.g. n_estimators, max_depth, C
MetricsEvery metric Keras reports, once per epoch: loss, accuracy, val_loss, val_accuracy…Training scores (e.g. training accuracy, F1, ROC-AUC for classifiers; RMSE, R² for regressors), plus scores you compute with sklearn.metrics on other data
ArtifactsA model summary text file and the trained modelThe fitted model; for classifiers, plots such as a confusion matrix; for searches, a table of all candidates
ExtrasEarly stopping information (e.g. the stopped epoch)GridSearchCV / RandomizedSearchCV create a parent run with one child run per candidate

Useful options

mlflow.tensorflow.autolog(
    log_models=True,      # set False to skip saving the model (faster, less disk)
    log_datasets=False,   # skip recording dataset information
    disable=False,        # True switches autologging off again
)

Autolog: strengths

  • Almost no code to write
  • Per-epoch curves for free
  • Consistent names across runs
  • The model is saved automatically

Autolog: limits

  • Doesn't know your data version, feature set or why you tried this run: add those as tags or params yourself
  • Doesn't log your holdout test score unless you log it
  • Can log more than you want (stray preprocessing runs, large models)

The course recommendation: autolog for the heavy lifting, plus a handful of manual log_params / set_tag / log_metric calls for the things only you know. This keeps your training code short and your runs informative.

7Naming and organising

Intuition. Good names let you understand the runs table at a glance in three weeks' time. Name experiments after the question, and runs after what is different about them.

Experiments: one per question

  • One experiment per dataset and task: adult-income-mlp, california-housing-mlp, fashion-mnist-cnn.
  • Runs inside one experiment should be comparable: same data split, same target, same main metric. If you change the split or the target, start a new experiment.
  • Avoid test, experiment1, samuel-stuff. Avoid putting everything in "Default".

Runs: say what changed

PatternExampleReads as
{model}-{arch}-{optimiser}-lr{lr}mlp-2x128-adam-lr1e-3MLP, 2 hidden layers of 128, Adam, learning rate 0.001
+ regularisationmlp-2x128-adam-lr1e-3-do0.3…with 30% dropout
CNNcnn-2conv32-64-dense128-adam-lr1e-3Two conv layers (32 and 64 filters), dense 128
Baselinebaseline-logregThe simple reference model

Generate the name from the config dictionary so it can't drift from the real settings:

cfg = {"layers": [128, 128], "optimiser": "adam", "lr": 1e-3, "dropout": 0.3}
run_name = f"mlp-{len(cfg['layers'])}x{cfg['layers'][0]}-{cfg['optimiser']}-lr{cfg['lr']:.0e}-do{cfg['dropout']}"
# -> "mlp-2x128-adam-lr1e-03-do0.3"

Tags worth adding to every run

TagExample valueWhy
data_versionadult-openml-v2Which data the run saw
git_commit8c6ba77Which code produced it (MLflow often records this itself as mlflow.source.git.commit when you run a script inside a git repository)

commit = subprocess.check_output(["git", "rev-parse", "--short", "HEAD"], text=True).strip()
mlflow.set_tags({"git_commit": commit, "data_version": "adult-openml-v2", "purpose": "tuning"})

For more structure, MLflow supports nested runs: a parent run (say, "lr-sweep") with child runs inside it, created with mlflow.start_run(nested=True). Useful for hyperparameter searches; optional this week.

8Logging figures and other artifacts

Intuition. Metrics are numbers; artifacts are everything else. A training-curve plot attached to the run is worth more than a plot in a notebook cell that gets overwritten.

A training-curve figure

import matplotlib.pyplot as plt

def plot_history(history):
    fig, ax = plt.subplots(figsize=(6, 4))
    ax.plot(history.history["loss"], label="training loss")
    ax.plot(history.history["val_loss"], label="validation loss")
    ax.set_xlabel("epoch"); ax.set_ylabel("loss"); ax.legend()
    ax.set_title("Training curve")
    return fig

with mlflow.start_run(run_name="mlp-2x128-adam-lr1e-3"):
    history = model.fit(X_train, y_train, validation_split=0.2, epochs=20, verbose=0)
    fig = plot_history(history)
    mlflow.log_figure(fig, "plots/training_curve.png")   # path inside the run's artifacts
    plt.close(fig)                                        # free memory in long loops

MLflow already draws metric curves in the UI, but a saved figure is handy for your GitHub README and your Tuesday presentation, and it shows exactly what you looked at.

Other useful artifacts

from sklearn.metrics import ConfusionMatrixDisplay
import pandas as pd

# A confusion matrix (classification)
disp = ConfusionMatrixDisplay.from_predictions(y_test, y_pred)
mlflow.log_figure(disp.figure_, "plots/confusion_matrix.png")

# Predictions as a CSV file
pd.DataFrame({"y_true": y_test, "y_pred": y_pred}).to_csv("predictions.csv", index=False)
mlflow.log_artifact("predictions.csv", artifact_path="outputs")

# The config used, as JSON
mlflow.log_dict(cfg, "config.json")

Don't log secrets or personal data. API keys, passwords, .env files and raw personal data must never become artifacts or parameters. Anyone with access to the tracking server can read them.

9Comparing runs in the UI

Intuition. The MLflow UI is a spreadsheet of your runs that you can sort, filter and chart. Pick the runs you care about, press Compare, and look at the curves together.

The layout changes a little between MLflow versions, but the main pieces are always there:

  1. Experiments list (left): click your experiment, e.g. adult-income-mlp.
  2. Runs table: one row per run. Use the Columns button to show the parameters and metrics you care about (for example learning_rate, val_accuracy, val_loss) and hide the rest.
  3. Sort by clicking a column header, e.g. val_loss ascending: the best run rises to the top.
  4. Filter with the search box, which accepts expressions such as params.optimizer = "adam" and metrics.val_accuracy > 0.85.
  5. Chart view: a tab or toggle that shows each metric as a chart, with one line or bar per run.
  6. Tick the checkboxes of two or more runs and press Compare. The comparison page shows:
    • a table of parameters and metrics side by side, with differences highlighted;
    • a parallel coordinates plot: one vertical axis per parameter or metric, one line per run, so you can see which settings lead to good scores;
    • scatter and contour plots of one parameter against a metric;
    • metric charts: per-epoch curves of, say, val_loss for every selected run on one chart.
  7. Click a run's name to open its run page: parameters, metrics, tags, and the Artifacts panel where your plots and model live.

Reading the comparison: look at the shape of the validation curves, not only the final number. A validation loss that falls and then rises is overfitting: the best epoch was earlier than the last one. A big gap between training accuracy and validation accuracy says the same thing.

Try it: a mock MLflow runs table
Illustrative example data, not real results: 8 Keras MLP runs on a tabular classification task. Click a header to sort. Filter with expressions like optimiser = adam, dropout > 0 or val_accuracy >= 0.85 and layers = 2. Tick runs and press Compare to draw their validation-loss curves.

Things to notice in the widget: the two deep runs without dropout reach a low validation loss early, then it climbs; their training accuracy is far above validation accuracy (flagged as possible overfitting). Ranking by the last val_loss and by the minimum val_loss can give different winners. That is why early stopping with restore_best_weights=True is worth using.

10Searching runs in code

Intuition. Everything you can see in the UI table you can also pull into a pandas DataFrame with mlflow.search_runs, then sort, filter and pick the best run in code.

import mlflow

runs = mlflow.search_runs(
    experiment_names=["adult-income-mlp"],
    filter_string="metrics.val_accuracy > 0.84 and attributes.status = 'FINISHED'",
    order_by=["metrics.val_accuracy DESC"],
    max_results=50,
)
print(type(runs))          # <class 'pandas.core.frame.DataFrame'>
print(runs.columns[:8])    # run_id, experiment_id, status, ..., metrics.*, params.*, tags.*

Each row is a run. Columns are named by their type: metrics.val_accuracy, params.learning_rate, tags.mlflow.runName, plus run_id, status, start_time and end_time.

Filter syntax

FilterMeaning
metrics.val_loss < 0.32Metrics are numbers: no quotes around the value
params.optimizer = 'adam'Params are stored as text: quote the value
tags.purpose = 'final'Tags are text too
tags.mlflow.runName LIKE 'mlp-2x%'Pattern match on the run name (% = anything)
... and ...Combine conditions with and (there is no or; run two searches instead)

Two traps. (1) Because params are text, sorting or comparing them in pandas sorts alphabetically ("0.01" before "0.001" is not numeric order); convert with pd.to_numeric. (2) metrics.val_loss is the last logged value, not the best one over all epochs.

Pick the best run and print a comparison table

best = runs.iloc[0]                                   # already ordered by val_accuracy
print("Best run:", best["tags.mlflow.runName"], best["run_id"])
print("val_accuracy:", round(best["metrics.val_accuracy"], 4))

cols = ["tags.mlflow.runName", "params.learning_rate", "metrics.val_loss", "metrics.val_accuracy"]
table = runs[[c for c in cols if c in runs.columns]]  # only columns that exist
print(table.to_string(index=False))

For per-epoch values (the whole curve, not just the last value) use the client:

from mlflow import MlflowClient

client = MlflowClient()
history = client.get_metric_history(best["run_id"], "val_loss")
curve = [(m.step, m.value) for m in history]
best_epoch, best_val_loss = min(curve, key=lambda t: t[1])

11Logging and loading models

Intuition. Logging a model saves it with its instructions: which library, which dependencies, what input it expects. Anyone can then load it with one line, without your training code.

Log a model

import mlflow

with mlflow.start_run(run_name="rf-baseline") as run:
    rf.fit(X_train, y_train)
    model_info = mlflow.sklearn.log_model(
        rf,
        name="model",                      # recent MLflow (3.x)
        input_example=X_train.iloc[:5],    # lets MLflow infer the input signature
    )

print(model_info.model_uri)                # use this URI to load or register the model

Version note: in recent MLflow (3.x) the model's name is given with name="model". Older MLflow 2.x code uses artifact_path="model" for the same thing, and you will see it in many tutorials. If one keyword raises an error or a deprecation warning, try the other, and check your version with mlflow.__version__.

For Keras the pattern is the same with the Keras or TensorFlow flavour, for example mlflow.tensorflow.log_model(model, name="model"), or mlflow.keras.log_model(...) for Keras 3 in recent MLflow. If you use autolog with log_models=True, the model is logged for you and you don't need this call.

Model URIs: how to point at a model

URIPoints at
model_info.model_uriExactly the model you just logged (the safest choice in code)
runs:/<run_id>/modelThe model logged under the name "model" in that run
models:/adult-income-classifier/3Version 3 of a registered model
models:/adult-income-classifier@championWhichever version currently has the alias champion

Load a model

# Generic: works for any flavour; gives you .predict()
model = mlflow.pyfunc.load_model(model_info.model_uri)
preds = model.predict(X_test)

# Native: gives you back the real Keras / scikit-learn object
rf_again = mlflow.sklearn.load_model(model_info.model_uri)
keras_model = mlflow.tensorflow.load_model("runs:/<run_id>/model")

pyfunc ("Python function") is MLflow's universal model interface: every flavour can be loaded as a pyfunc with a predict method. That is what serving tools and the Week 3 pipeline use, because they don't need to know which library trained the model. For a Keras classifier, predict returns what the network outputs, such as probabilities, so apply your threshold afterwards.

12The model registry

Intuition. The registry is a shelf of named models. Each time you add a new version it gets the next number. Aliases are sticky labels such as "champion" that you move from version to version, so other code can always ask for "the champion" without knowing its number.

Key ideas

TermMeaningExample
Registered modelA named entry in the registryadult-income-classifier
VersionA numbered snapshot of a model, linked to the run that produced it. Numbers go 1, 2, 3… and are never reusedVersion 3
AliasA movable, named pointer to one version. Each alias points at one version at a time; setting it on another version moves it@champion → version 3
Model version tagA label on a versionvalidation_status = approved

Register a model

import mlflow

# Option A: register while logging
model_info = mlflow.sklearn.log_model(rf, name="model",
                                      registered_model_name="adult-income-classifier")

# Option B: register an already-logged model
mv = mlflow.register_model(model_info.model_uri, "adult-income-classifier")
print(mv.name, mv.version)       # adult-income-classifier 1

If the registered model doesn't exist yet, it is created and this becomes version 1. Registering again creates version 2, and so on.

Set aliases and load by alias

from mlflow import MlflowClient

client = MlflowClient()
client.set_registered_model_alias("adult-income-classifier", "champion", 1)
client.set_registered_model_alias("adult-income-classifier", "challenger", 2)

# Which version is the champion right now?
mv = client.get_model_version_by_alias("adult-income-classifier", "champion")
print(mv.version, mv.run_id)

# Load the champion: this code never changes, even when the champion does
champion = mlflow.pyfunc.load_model("models:/adult-income-classifier@champion")

# Remove an alias
client.delete_registered_model_alias("adult-income-classifier", "challenger")

# Add a tag to a version
client.set_model_version_tag("adult-income-classifier", "2", "validation_status", "approved")

Stages are deprecated. Older tutorials move versions between fixed stages ("Staging", "Production", "Archived") with transition_model_version_stage. MLflow has deprecated stages in favour of aliases (and version tags), which are more flexible: you choose the names, and a version can have several aliases. Use aliases on this course.

The UI has a Models tab where you can see registered models, their versions, which run each came from, and their aliases. You can also register a model from a run page by opening the model in the Artifacts panel and choosing "Register model".

13Champion vs challenger

Intuition. The champion is the model currently in use. A new model, the challenger, has to beat it in a fair contest (same data, same metric, a rule agreed in advance) before it takes the title.

The workflow

1. Train challenger
new data / new settings

  • Same holdout set: a fixed set of rows that neither model trained on. Comparing a challenger's validation score with a champion's old test score is not a fair contest.
  • Same metric, decided before you look at the results.
  • A margin: requiring the challenger to win by at least, say, 0.5 percentage points avoids swapping models over tiny differences that are just noise.
  • Promotion is just moving an alias. Anything that loads models:/<name>@champion picks up the new version automatically. Rolling back is moving the alias back.
from mlflow import MlflowClient
from sklearn.metrics import accuracy_score
import mlflow

NAME, MARGIN = "adult-income-classifier", 0.005      # 0.5 percentage points
client = MlflowClient()

def holdout_accuracy(alias):
    model = mlflow.pyfunc.load_model(f"models:/{NAME}@{alias}")
    proba = model.predict(X_holdout)                   # same holdout for both
    return accuracy_score(y_holdout, (proba >= 0.5).astype(int).ravel())

champ_acc, chall_acc = holdout_accuracy("champion"), holdout_accuracy("challenger")
challenger = client.get_model_version_by_alias(NAME, "challenger")

with mlflow.start_run(run_name="champion-vs-challenger"):
    mlflow.log_metrics({"champion_acc": champ_acc, "challenger_acc": chall_acc})
    if chall_acc >= champ_acc + MARGIN:
        client.set_registered_model_alias(NAME, "champion", challenger.version)
        mlflow.set_tag("decision", f"promoted v{challenger.version}")
    else:
        mlflow.set_tag("decision", "kept champion")

    14Worked example: three Keras runs on Adult Census Income

    Intuition. Prepare the data once, loop over three configurations, let autolog record each run, add the details only you know, then pull everything back with search_runs and print a comparison table.

    The task: predict whether a person's income is above $50K from census attributes (binary classification). The same structure works for California Housing (change the loss to "mse", the output layer to Dense(1) with no activation, and the metric to RMSE) and for Fashion-MNIST (swap in a CNN).

    Step 1: data, prepared once

    import mlflow
import keras
from sklearn.datasets import fetch_openml
from sklearn.model_selection import train_test_split
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import OneHotEncoder, StandardScaler

EXPERIMENT = "adult-income-mlp"
DATA_VERSION = "openml-adult-v2"

adult = fetch_openml("adult", version=2, as_frame=True)
X = adult.data
y = (adult.target == ">50K").astype("int32")

# Holdout test set: never used for choosing between runs
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42)

num_cols = X.select_dtypes("number").columns
cat_cols = X.select_dtypes(exclude="number").columns
prep = ColumnTransformer([
    ("num", StandardScaler(), num_cols),
    ("cat", OneHotEncoder(handle_unknown="ignore", sparse_output=False), cat_cols),
])
X_train_p = prep.fit_transform(X_train).astype("float32")   # fit on training data only
X_test_p = prep.transform(X_test).astype("float32")

    Step 2: three configurations in a loop

    CONFIGS = [
    {"layers": [64],       "lr": 1e-3, "dropout": 0.0},   # small baseline
    {"layers": [128, 128], "lr": 1e-3, "dropout": 0.3},   # deeper + dropout
    {"layers": [128, 128], "lr": 1e-2, "dropout": 0.3},   # same, higher learning rate
]

def build_model(n_features, layers, lr, dropout):
    model = keras.Sequential([keras.Input(shape=(n_features,))])
    for units in layers:
        model.add(keras.layers.Dense(units, activation="relu"))
        if dropout:
            model.add(keras.layers.Dropout(dropout))
    model.add(keras.layers.Dense(1, activation="sigmoid"))
    model.compile(optimizer=keras.optimizers.Adam(learning_rate=lr),
                  loss="binary_crossentropy", metrics=["accuracy"])
    return model

def run_name(cfg):
    return f"mlp-{len(cfg['layers'])}x{cfg['layers'][0]}-adam-lr{cfg['lr']:.0e}-do{cfg['dropout']}"

mlflow.set_experiment(EXPERIMENT)
mlflow.tensorflow.autolog(log_models=True)   # Keras only; mlflow.keras.autolog() in recent MLflow with Keras 3

for cfg in CONFIGS:
    keras.utils.set_random_seed(42)          # same seed for every run: a fair comparison
    with mlflow.start_run(run_name=run_name(cfg)):
        # Extra params autolog can't know. Prefixed "cfg_" so they never clash with autolog's names.
        mlflow.log_params({"cfg_hidden_layers": len(cfg["layers"]),
                           "cfg_units": str(cfg["layers"]),
                           "cfg_dropout": cfg["dropout"],
                           "cfg_learning_rate": cfg["lr"]})
        mlflow.set_tags({"data_version": DATA_VERSION, "purpose": "week2-comparison"})

        model = build_model(X_train_p.shape[1], cfg["layers"], cfg["lr"], cfg["dropout"])
        early_stop = keras.callbacks.EarlyStopping(monitor="val_loss", patience=3,
                                                   restore_best_weights=True)
        model.fit(X_train_p, y_train, validation_split=0.2, epochs=30,
                  batch_size=256, callbacks=[early_stop], verbose=0)

        # The holdout score, logged by hand (autolog doesn't do this)
        test_loss, test_acc = model.evaluate(X_test_p, y_test, verbose=0)
        mlflow.log_metrics({"test_loss": test_loss, "test_accuracy": test_acc})

    Autolog records the epochs, batch size, optimiser settings, per-epoch loss, accuracy, val_loss and val_accuracy, and the model. Our manual calls add the architecture, the data version and the holdout score.

    Step 3: compare in code

    import pandas as pd

runs = mlflow.search_runs(experiment_names=[EXPERIMENT],
                          filter_string="tags.purpose = 'week2-comparison'",
                          order_by=["metrics.val_accuracy DESC"])

cols = ["tags.mlflow.runName", "params.cfg_units", "params.cfg_dropout",
        "params.cfg_learning_rate", "metrics.val_loss", "metrics.val_accuracy",
        "metrics.accuracy", "metrics.test_accuracy"]
table = runs[[c for c in cols if c in runs.columns]].copy()
table.columns = [c.split(".")[-1] for c in table.columns]          # shorter headers
table["gap"] = table["accuracy"] - table["val_accuracy"]           # train − validation
print(table.round(4).to_string(index=False))

best = runs.iloc[0]
print(f"\nBest by validation accuracy: {best['tags.mlflow.runName']} (run {best['run_id'][:8]})")

    15Good practices

    Intuition. Track as if a stranger has to reproduce your best model from the MLflow UI alone, without asking you anything.

    Organise

    • One experiment per project or question
    • Descriptive run names generated from the config
    • Same split and main metric for every run in an experiment

    Reproduce

    • Set seeds (keras.utils.set_random_seed(42), random_state=42)
    • Log the data version and git commit as tags
    • Commit your code before a batch of "real" runs

    Compare fairly

    • Choose on validation, report on the holdout test set
    • Look at curves, not just final numbers
    • Change one thing at a time when you can

    Stay safe and tidy

    • Never log secrets, .env files or personal data
    • Keep mlruns/, mlartifacts/, mlflow.db out of git
    • Delete broken test runs in the UI so the table stays readable

    Even with seeds, GPU training is not always bit-for-bit repeatable. Small run-to-run differences (say ±0.2 points) are normal. That is one more reason to use a margin when promoting a challenger.

    Your Week 2 checklist

    1. Train at least 3 deep learning models (different architectures and/or learning rates) on one of: Adult Census Income (classification), California Housing (regression) or Fashion-MNIST (CNN).
    2. Use mlflow.autolog() (or the Keras/TensorFlow flavour) plus a few manual params and tags.
    3. Every run is in a clearly named experiment with a descriptive run name.
    4. Compare runs in the MLflow UI: sorted table, the Compare page, and the val_loss metric chart.
    5. Take screenshots of the runs table and the comparison charts for your README.
    6. Push code and screenshots to GitHub, with mlruns/ and mlartifacts/ in .gitignore.
    7. Prepare the Tuesday presentation: which run won, by which metric, what the curves show (any overfitting?), and what you would try next.

    16Troubleshooting

    Intuition. Most MLflow problems come down to "the code and the UI are looking at different places".

    SymptomLikely causeFix
    The UI shows no runs, or an old set of runsThe UI was started in a different folder from your notebook, or your code sets a tracking URI the UI isn't usingPrint mlflow.get_tracking_uri() in your code. Start the UI from the same folder, or pass the same store: mlflow ui --backend-store-uri sqlite:///mlflow.db
    Runs are in "Default", not my experimentset_experiment was not called, or was called after the run startedCall mlflow.set_experiment("...") before start_run
    Port 5000 is already in useAnother MLflow UI is still running, or another program uses the port (on macOS, often the AirPlay Receiver)uv run mlflow ui --port 5001 and open http://127.0.0.1:5001
    MlflowException about changing a param valueThe same param key was logged twice with different values (often you and autolog)Rename your own params (e.g. a cfg_ prefix) or stop logging that one manually
    Runs stay "RUNNING" foreverA notebook cell crashed outside a with block, leaving the run openUse with mlflow.start_run():; call mlflow.end_run() to close a stuck run
    "Run … is already active"You started a run while another one is still openmlflow.end_run() first, or use nested=True on purpose
    Lots of unexpected extra runsGeneric mlflow.autolog() also logged scikit-learn preprocessing fitsUse mlflow.tensorflow.autolog() (or mlflow.keras.autolog()) instead
    Registry calls fail with a message that the registry is unavailable or unsupportedSome older setups don't support the registry on a plain file storeUse a database store: mlflow.set_tracking_uri("sqlite:///mlflow.db"), and start the UI with the same URI
    log_model complains about name or artifact_pathThe keyword differs between MLflow versionsCheck mlflow.__version__: recent versions use name=; older ones artifact_path=
    git status shows thousands of filesThe local store is not ignoredAdd mlruns/, mlartifacts/, mlflow.db to .gitignore; if already committed, git rm -r --cached mlruns
