Exploratory data analysis & data preprocessing

Before any model, you need to understand your data and get it into a shape a model can use. This guide walks through both steps on the Titanic passenger dataset: looking, questioning, cleaning, encoding, scaling and engineering features, and finally wrapping it all in a leak-proof scikit-learn pipeline.

1What EDA is, and why it comes first

Intuition. A doctor examines the patient before prescribing. EDA is the examination: you look at the data from every angle before you decide what to do with it.

Exploratory data analysis (EDA) means summarising and visualising a dataset to understand what is in it, what is wrong with it, and which patterns might be useful. Data preprocessing is what comes next: fixing the problems EDA found and converting the data into numbers a model can learn from.

Why it comes first

  • Garbage in, garbage out. A model learns whatever is in the data, including typing errors, duplicated rows and impossible values.
  • Models need numbers. Most scikit-learn models cannot read text such as "male" or handle empty cells. Preprocessing converts and fills them.
  • It shapes every later decision: which columns to keep, how to fill gaps, which model family suits the data, and which metric to use.
  • It catches traps early, such as a column that secretly contains the answer (see data leakage).

The running example: Titanic

We use the Kaggle Titanic train.csv: 891 rows (one per passenger) and 12 columns. The task is to predict Survived (1 = survived, 0 = did not). The column we want to predict is called the target; the columns we use to predict it are the features.

First-look checklist

  • How many rows and columns? Is that what you expected?
  • Which column is the target? Is it balanced?
  • Are the dtypes right (numbers stored as text, dates stored as text)?
  • Which columns have missing values, and how many?
  • Do the min and max make sense (negative ages, zero prices)?
  • Which columns are identifiers or free text that need special handling?

A number is not always a quantity. Postcodes, phone numbers and class codes are digits, but averaging them is meaningless. Ask: "would it make sense to add two of these together?" If not, it is categorical.

Try it: survival rate by group
The result of df.groupby(col)["Survived"].mean() on the 891 training passengers. The dashed line is the overall survival rate.

Correlation (Pearson's r) measures how strongly two numeric columns move together in a straight line, from −1 (perfectly opposite) through 0 (no linear link) to +1 (perfectly together). On Titanic, Pclass and Fare are negatively correlated: a smaller class number (first class) goes with a higher fare. Correlation ignores curved relationships and categories, and it never proves causation.

Watch for confounding. A confounder is a third variable that drives two others. Fare and survival are linked, but much of that link runs through class: first-class passengers paid more and had cabins nearer the lifeboats. Splitting by a second variable (groupby(["Pclass", "Sex"])) helps you see this.

5Missing data

Intuition. An empty cell is a question, not just a gap: why is it empty? The answer decides whether you can safely drop it, fill it, or treat "missing" as information in itself.

Detecting it

df.isnull().sum()                                  # count per column (isna() is identical)
(df.isnull().mean() * 100).round(1)                # percentage per column
df.isnull().sum().sort_values(ascending=False)     # worst first
df[df["Embarked"].isnull()]                        # look at the actual rows
Missing values per column
The output of df.isnull().sum() on Titanic train.csv (891 rows), drawn as bars.
  • Age: 177 missing (19.9%). Too many to drop the rows, few enough to fill sensibly.
  • Cabin: 687 missing (77.1%). Most of the column is empty. Filling it would be mostly invention.
  • Embarked: 2 missing. Trivial: fill with the most common port (S) or drop the two rows.

Why is it missing? MCAR, MAR, MNAR

TypePlain EnglishExampleConsequence
MCAR
missing completely at random		The gap has nothing to do with anything: pure bad luckA clerk spilt ink on two boarding records (plausible for Embarked)Dropping or simple filling does not bias results; you only lose data
MAR
missing at random		The gap depends on other columns you can seeIf ages were recorded less often for third-class passengers, missingness depends on PclassFill using those other columns (group-wise median, model-based imputation)
MNAR
missing not at random		The gap depends on the missing value itselfPeople with high incomes leave the "income" box empty; cabins were largely recorded for wealthier passengersDangerous: any fill is biased. Add a missing-indicator flag and treat "missing" as a signal
 
# Is Age missingness related to other columns? (a quick MAR check)
df["Age_missing"] = df["Age"].isnull()
df.groupby("Pclass")["Age_missing"].mean()     # different rates across classes → not MCAR
df.groupby("Age_missing")["Survived"].mean()   # does missingness relate to the target?

Drop or impute?

SituationUsual choiceTitanic
Very few rows missing (well under 5%), probably MCARDrop those rows (dropna(subset=[...])) or fill with the mode/medianEmbarked
A moderate share missing (roughly 5–40%) in a useful columnImpute, and consider a missing-indicator flagAge
Most of the column missing (over about 60%)Drop the column, or reduce it to "known / unknown"Cabin → HasCabin
The target itself is missingDrop those rows: you cannot learn from them(none)

These percentages are rules of thumb, not laws. Always ask how important the column is and why it is missing.

df = df.dropna(subset=["Embarked"])          # drop the 2 rows (or fill with mode instead)
df = df.drop(columns=["Cabin"])              # drop a mostly-empty column...
# ...or keep its signal:
df["HasCabin"] = df["Cabin"].notna().astype(int)

# Missing-indicator flag: remember WHICH values were filled
df["Age_missing"] = df["Age"].isna().astype(int)
df["Age"] = df["Age"].fillna(df["Age"].median())

Missing-indicator flags are cheap insurance. After filling, the model can no longer tell a real 28-year-old from a filled-in 28. The extra 0/1 column lets it learn whether "age unknown" matters on its own. In scikit-learn, SimpleImputer(add_indicator=True) does this for you.

Do not drop rows blindly. df.dropna() with no arguments drops every row with any gap. On Titanic, Cabin alone would wipe out 687 of 891 rows (77%).

6Duplicates

Intuition. A duplicated row counts the same event twice. The model then over-weights it, and if one copy lands in training and the other in testing, your test score is flattered.

df.duplicated().sum()                      # Titanic: 0 fully duplicated rows

# Which rows are duplicates? keep=False marks ALL copies (default keep="first" marks only the later ones)
df[df.duplicated(keep=False)]

# Duplicates on a subset of columns, e.g. same name and ticket but a different id
df.duplicated(subset=["Name", "Ticket"]).sum()

df = df.drop_duplicates()                              # keep the first copy
df = df.drop_duplicates(subset=["Name", "Ticket"], keep="last")
ArgumentMeaning
keep="first" (default)Mark/keep the first occurrence; later copies count as duplicates
keep="last"Keep the last occurrence (useful if later rows are corrections)
keep=FalseMark every copy, so you can inspect them all side by side
subset=[...]Compare only these columns. An ID column makes every row unique, so exclude it to find real repeats

Not every repeat is an error. Two different passengers can share a ticket number (families travelled on one ticket), so duplicated Ticket values are real. Decide what "the same record" means for your data before deleting anything. Also check for near-duplicates, such as "S" vs " s"; clean them with .str.strip().str.upper().

7Outliers

Intuition. An outlier is a value far from the rest. It might be a typing mistake, or it might be the most interesting row in the dataset. Find it, then investigate before you touch it.

The box plot and the IQR rule

Sort the values and cut them into quarters. Q1 (the 25th percentile) has a quarter of the values below it; Q3 (the 75th percentile) has three-quarters below it. The interquartile range (IQR) is the width of the middle half:

IQR = Q3 − Q1

lower bound = Q1 − 1.5 × IQR  ·  upper bound = Q3 + 1.5 × IQR

Anything outside the bounds is flagged as an outlier. The 1.5 is a convention; 3 flags only "extreme" outliers. A box plot draws exactly this: the box is Q1 to Q3, the line inside is the median, the whiskers reach the furthest points still inside the bounds, and the dots beyond are the outliers.

On Titanic Fare, the upper bound is about 65.63 and 116 passengers lie above it. About 90% of them travelled first class. These are not errors: expensive tickets for first-class passengers are exactly what you would expect. The maximum, 512.33, is a real fare.

q1, q3 = df["Fare"].quantile([0.25, 0.75])
iqr = q3 - q1
lower, upper = q1 - 1.5 * iqr, q3 + 1.5 * iqr       # upper ≈ 65.63
outliers = df[(df["Fare"] < lower) | (df["Fare"] > upper)]
len(outliers)                                       # 116
outliers["Pclass"].value_counts(normalize=True)     # about 90% first class
Try it: outlier explorer
40 fare-like values (made up, right-skewed like the real Fare). Change the IQR multiplier, cap the outliers, or apply a log transform and see how the picture changes.

The z-score rule

A z-score says how many standard deviations a value is from the mean: z = (x − mean) / std. A common rule flags |z| > 3. It works well for roughly bell-shaped data, but on skewed data the outliers themselves inflate the mean and standard deviation, which hides them. The IQR rule uses quartiles, which outliers barely move, so it is more robust (less affected by extreme values).

z = (df["Fare"] - df["Fare"].mean()) / df["Fare"].std()
df[z.abs() > 3]

Genuine or error?

Probably an error

  • Impossible values: age −5, age 250, a negative price
  • Unit mix-ups: a height of 1.8 among values like 180
  • Placeholder codes: 999, −1, 0 meaning "unknown"
  • Typos: an extra zero

Probably genuine

  • Rare but possible: a 512 fare in first class
  • Explained by another column (first class, a large group ticket)
  • The very thing you want to detect (fraud, faults)

What to do about them

OptionHowWhen
KeepDo nothingGenuine values, and a model that copes (tree-based models barely care)
Cap / clip (winsorise)df["Fare"].clip(lower, upper)Genuine but extreme values that would dominate a linear model
Transformnp.log1p(df["Fare"])Right-skewed, positive data (prices, incomes). Squashes the tail, keeps the order
Removedf = df[df["Age"].between(0, 110)]Clear errors only, and only when you cannot fix them
Fix / set to missingdf["Age"] = df["Age"].replace(999, np.nan)Placeholder codes, then impute as normal

Never delete outliers just because a rule flagged them. On Titanic, removing the 116 "outlier" fares would delete a large share of first-class passengers, exactly the group with the highest survival rate, and bias the model.

log1p(x) means log(1 + x). The "+1" stops it breaking on zero, which matters because some Titanic fares are exactly 0.

8Imputation: filling the gaps

Intuition. Imputation means replacing a missing value with a sensible guess. The simplest guess is a "typical" value for the column; smarter guesses use the other columns.

MethodFills withUse forWatch out
MeanThe averageSymmetric numeric data without outliersPulled by outliers and skew
MedianThe middle valueSkewed numeric data or data with outliers (Age, Fare). A safe defaultIgnores relationships with other columns
Mode (most frequent)The most common valueCategorical columns (Embarked → S)Inflates the most common category
ConstantA fixed value such as "Unknown" or 0Categories where "missing" is meaningful (Cabin → "Unknown")Numeric constants such as 0 can be misleading
Group-wise medianThe median of similar rowsMAR data: fill Age by the median of the same Sex and PclassGroups must be big enough to have a stable median
Forward fillThe previous value in timeTime series (sensor readings, daily prices)Only valid when rows are sorted in time
KNN imputerThe average of the k most similar rowsColumns that relate to others in non-simple waysNeeds scaling; slower
Iterative imputerA prediction from a model of the other columnsSeveral related columns with gapsMost complex; still experimental in scikit-learn
Try it: imputation playground
20 age-like values (made up), 5 of them missing, plus two elderly passengers (80 and 74). Choose a strategy; filled values are highlighted in blue.

Why the median resists outliers. The mean adds up every value, so one 80 pulls it up noticeably. The median only cares about the middle position: making the largest value bigger does not change which value sits in the middle. Untick the two large values in the playground: the mean drops by about 6 years, the median by 1.

Any single-value fill shrinks the spread. Putting the same number into many gaps adds rows exactly at the centre, so the standard deviation falls and the distribution gets an artificial spike. That is one reason to add a missing-indicator flag, and to prefer group-wise or model-based imputation when many values are missing.

import numpy as np

# Simple pandas fills
df["Age"]      = df["Age"].fillna(df["Age"].median())
df["Embarked"] = df["Embarked"].fillna(df["Embarked"].mode()[0])   # mode() returns a Series
df["Cabin"]    = df["Cabin"].fillna("Unknown")

# Group-wise median: each passenger gets the median age of their own Sex × Pclass group
df["Age"] = df["Age"].fillna(df.groupby(["Sex", "Pclass"])["Age"].transform("median"))

# Time series: carry the last known value forward
# readings["temp"] = readings.sort_values("time")["temp"].ffill()

# scikit-learn imputers (use these inside a pipeline, see section 12)
from sklearn.impute import SimpleImputer, KNNImputer
from sklearn.experimental import enable_iterative_imputer   # noqa: F401, required import
from sklearn.impute import IterativeImputer

SimpleImputer(strategy="median", add_indicator=True)       # also: "mean", "most_frequent", "constant"
KNNImputer(n_neighbors=5)
IterativeImputer(random_state=42)

Compute fill values on the training data only. df["Age"].median() on the whole dataset includes the test rows, a small but real form of leakage. Pandas fills are fine for exploring; for modelling, put the imputer in a pipeline.

9Encoding categorical variables

Intuition. Models do maths, so categories must become numbers. The trick is to do it without inventing an order or a distance that does not exist.

Label and ordinal encoding

Label encoding replaces each category with an integer: female → 0, male → 1. Ordinal encoding does the same but in an order you choose, for categories that really are ordered.

# Binary column: a simple mapping is fine
df["Sex_code"] = df["Sex"].map({"female": 0, "male": 1})

# Ordinal column: choose the order deliberately
size_order = {"small": 0, "medium": 1, "large": 2}
# shop["size_code"] = shop["size"].map(size_order)

from sklearn.preprocessing import OrdinalEncoder
OrdinalEncoder(categories=[["small", "medium", "large"]])

One-hot encoding

One-hot encoding creates one 0/1 column per category. A passenger who embarked at Cherbourg gets Embarked_C = 1, Embarked_Q = 0, Embarked_S = 0. No order, no distances: every category is equally different from every other.

# Quick, for exploration
pd.get_dummies(df, columns=["Embarked", "Sex"], drop_first=False, dtype=int)

# For modelling: remembers the categories seen in training
from sklearn.preprocessing import OneHotEncoder
ohe = OneHotEncoder(handle_unknown="ignore")    # unseen category at prediction time → all zeros, no crash
ohe.fit(X_train[["Embarked"]])
ohe.get_feature_names_out()                     # ['Embarked_C', 'Embarked_Q', 'Embarked_S']

Why OneHotEncoder over get_dummies for models? get_dummies creates columns from whatever is in the data it is given. If the test set lacks a category, or has a new one, its columns will not match the training columns. OneHotEncoder learns the categories once, on the training data, and handle_unknown="ignore" encodes anything new as all zeros instead of raising an error.

Why not label-encode nominal categories?

If you encode Embarked as C = 0, Q = 1, S = 2, a linear model reads that as "S is twice Q" and "Q sits between C and S". That order is invented by the alphabet. The model may then learn nonsense such as "survival changes steadily from C through Q to S".

Label / ordinal encoding is fine for

  • Binary columns (Sex)
  • Truly ordered categories (Pclass, sizes, education levels)
  • Tree-based models, which split on thresholds and are less fooled by a fake order

Avoid it for

  • Nominal categories with 3 or more values (Embarked) in linear models, SVMs, KNN and neural networks
  • Anywhere distance or "bigger than" would be meaningless

High cardinality

Cardinality is the number of distinct values. Ticket and Cabin have hundreds. One-hot encoding them creates hundreds of sparse columns, mostly with a single 1, which invites overfitting.

  • Extract structure: the deck letter from Cabin ("C85" → "C"), a title from Name.
  • Group rare categories into "Other" (OneHotEncoder(min_frequency=10) or max_categories=).
  • Frequency encoding: replace each category with how often it occurs.
  • Target encoding: replace each category with the average target for that category. Powerful but leaks easily; only use it with cross-fitting (scikit-learn's TargetEncoder does this).
  • Or drop the column if it is essentially an identifier.

10Feature scaling

Intuition. Age runs from 0 to 80, Fare from 0 to 512. For a model that measures distances, a difference of 50 in Fare would swamp a difference of 50 years in Age. Scaling puts features on comparable rulers.

ScalerFormulaResultBest for
Min-max (MinMaxScaler)(x − min) / (max − min)Values in [0, 1]Bounded data, neural network inputs, images. Sensitive to outliers: one 512 squashes everyone else near 0
Standardisation (StandardScaler)(x − mean) / stdMean 0, standard deviation 1 (z-scores)The usual default: linear and logistic regression, SVM, PCA
Robust (RobustScaler)(x − median) / IQRMedian 0; outliers stay large but do not distort the restData with outliers (Fare)

Which models need scaling?

Need scaling

  • K-nearest neighbours, k-means (distance-based)
  • Support vector machines
  • Linear and logistic regression with regularisation
  • Neural networks (and gradient descent in general)
  • PCA

Do not need scaling

  • Decision trees
  • Random forests, extra trees
  • Gradient boosting (XGBoost, LightGBM, CatBoost)
  • Naive Bayes (mostly)

Trees split on "is Fare > 50?", and the answer is the same whatever the units.

A 5-row mini table (made-up but Titanic-like). Apply a scaler to the numeric columns and encode the categorical ones. Changed cells are highlighted.

from sklearn.preprocessing import MinMaxScaler, StandardScaler, RobustScaler

scaler = StandardScaler()
X_train[["Age", "Fare"]] = scaler.fit_transform(X_train[["Age", "Fare"]])   # learn mean/std on TRAIN

scaler.mean_, scaler.scale_     # the learned parameters

Scale numeric features only, not one-hot 0/1 columns (they are already on a 0–1 scale) and not the target. StandardScaler uses the population standard deviation (dividing by n), so its numbers differ slightly from pandas' .std(), which divides by n − 1.

df["IsAlone"]    = (df["FamilySize"] == 1).astype(int)

# "Braund, Mr. Owen Harris" → "Mr"
df["Title"] = df["Name"].str.extract(r",\s*([^\.]+)\.", expand=False).str.strip()
df["Title"] = df["Title"].replace({"Mlle": "Miss", "Ms": "Miss", "Mme": "Mrs"})
common = ["Mr", "Mrs", "Miss", "Master"]
df["Title"] = df["Title"].where(df["Title"].isin(common), "Rare")   # group rare titles

df["AgeBand"] = pd.cut(df["Age"], bins=[0, 12, 18, 35, 60, 120],
                       labels=["child", "teen", "young adult", "adult", "senior"])
df["HasCabin"] = df["Cabin"].notna().astype(int)
df["Deck"]     = df["Cabin"].str[0].fillna("Unknown")
df["FarePerPerson"] = df["Fare"] / df["FamilySize"]

df.groupby("Title")["Survived"].agg(["mean", "count"])   # check the feature is informative

Title also helps imputation. "Master" was used for boys, so the median age of passengers titled Master is a much better guess for a missing age than the overall median. Group-wise imputation by Title is a classic Titanic trick.

Rule-based features are safe; data-based features need care. FamilySize uses only the row itself, so it can be computed on all data. Anything learned from the data (bin edges from quantiles, frequency counts, target means) must be learned from the training set only.

12Data leakage, fit-on-train-only, and pipelines

Intuition. The test set is a sealed exam paper. Data leakage is any way information from the exam sneaks into revision: the score looks brilliant, then the model fails on genuinely new data.

Common forms of leakage

LeakExampleFix
Preprocessing on all dataScaling or imputing with the mean of train + testSplit first; fit on train, transform both
Target leakageA feature recorded after the outcome (e.g. a lifeboat number for Titanic, "account closed date" for churn)Ask: "would I know this value at prediction time?" If not, drop it
Duplicates across the splitThe same row in train and testDeduplicate before splitting
Time leakageTraining on the future to predict the pastSplit by time for time-ordered data
Tuning on the test setTrying many settings and picking the best test scoreUse cross-validation on train; touch the test set once

fit vs transform

  • fit: learn parameters from data (the median, the mean and std, the list of categories).
  • transform: apply those learned parameters.
  • fit_transform: both, on the same data. Use it on training data only.

The leak-proof way: Pipeline + ColumnTransformer

A Pipeline chains steps so that calling fit fits every step on the training data in order. A ColumnTransformer applies different preprocessing to different columns. Together, they guarantee that the same steps run the same way at training and prediction time, and that cross-validation refits them inside each fold.

import pandas as pd
from sklearn.model_selection import train_test_split, cross_val_score
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.linear_model import LogisticRegression

df = pd.read_csv("train.csv")
df["FamilySize"] = df["SibSp"] + df["Parch"] + 1          # row-wise rule: safe before the split

X = df.drop(columns=["Survived", "PassengerId", "Name", "Ticket", "Cabin"])
y = df["Survived"]
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42)

numeric     = ["Age", "Fare", "SibSp", "Parch", "FamilySize"]
categorical = ["Sex", "Embarked", "Pclass"]

numeric_pipe = Pipeline([
    ("impute", SimpleImputer(strategy="median", add_indicator=True)),
    ("scale",  StandardScaler()),
])
categorical_pipe = Pipeline([
    ("impute", SimpleImputer(strategy="most_frequent")),
    ("onehot", OneHotEncoder(handle_unknown="ignore")),
])
preprocess = ColumnTransformer([
    ("num", numeric_pipe, numeric),
    ("cat", categorical_pipe, categorical),
])

model = Pipeline([
    ("preprocess", preprocess),
    ("clf", LogisticRegression(max_iter=1000)),
])

print(cross_val_score(model, X_train, y_train, cv=5).mean())  # preprocessing refit in every fold
model.fit(X_train, y_train)                                   # fit everything on train only
print(model.score(X_test, y_test))                            # one honest test score

Here Pclass is one-hot encoded. You could instead pass it through as an ordinal number (1, 2, 3); try both and compare with cross-validation.

Bonus: the fitted pipeline is one object. Save it with joblib.dump(model, "model.joblib"), and at prediction time raw data goes in and predictions come out, with exactly the same imputation, encoding and scaling.
