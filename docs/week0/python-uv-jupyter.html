Python projects and environments with uv, VS Code and Jupyter

Before you write any data science code, you need a reliable place to run it. This page explains why every project gets its own environment, how to install VS Code and uv, the handful of uv commands you will use every day (uv init, uv venv, uv add, uv run, uv sync), and how to connect it all to VS Code and Jupyter. Come back to it whenever something "can't find a module".

1Why environments exist

Intuition. Each project gets its own sealed toolbox. What you install for one project can never break another, and a teammate can rebuild exactly the same toolbox from a list.

Python code almost always depends on other people's code: packages such as pandas, NumPy or scikit-learn. Each package comes in many versions, and versions change behaviour. Three problems follow from that.

ProblemWhat it looks likeHow environments help
Dependency conflictsLast year's project needs pandas 1.5. This year's needs pandas 2.2. There is only one "pandas" slot on your computer, so installing one breaks the other.Each project has its own folder of packages, so both versions can exist side by side.
ReproducibilityYour model scored 0.87 in March. In June, after "a few updates", it scores 0.84 and nobody knows why.A lock file records the exact version of every package, so you can rebuild the March environment.
"Works on my machine"Your notebook runs for you but crashes for your teammate with ModuleNotFoundError or a strange error deep inside a library.Everyone builds their environment from the same files in the repository, so everyone runs the same code.
Try it: one shared Python vs one environment per project
Project A needs pandas<2. Project B needs pandas>=2.2. Choose a set-up, then install each project's requirements and see which projects still run.

2Interpreters, packages and virtual environments

Intuition. The interpreter is the engine, packages are the add-ons, and a virtual environment is a private garage that pairs one engine with one set of add-ons for one project.

When a virtual environment is active (or when you use uv run), typing python runs that environment's interpreter, and import pandas looks only in that environment's site-packages. That is why "it's installed but Python can't find it" almost always means it's installed somewhere else.

The system Python is not yours. macOS and Linux ship a Python that the operating system itself uses. Installing packages into it can break system tools, and recent Linux distributions block it outright (an "externally managed environment" error). Always work inside a project environment.

3Install VS Code

Intuition. VS Code is the editor where you write code, run notebooks and use a terminal, all in one window. It is free and works on macOS, Windows and Linux.

  1. Go to code.visualstudio.com and download the installer for your operating system. Make sure the address really is that site (Microsoft's official page).
  2. macOS: open the downloaded .zip, drag Visual Studio Code.app into Applications. Windows: run the User Installer and tick "Add to PATH" (it is ticked by default). Linux: use the .deb or .rpm package for your distribution.
  3. Open VS Code. Open the Extensions view (the four-squares icon on the left, or Ctrl+Shift+X / Cmd+Shift+X) and install:
    • Python (publisher: Microsoft). It also installs Pylance for autocompletion and the Python Debugger.
    • Jupyter (publisher: Microsoft) for .ipynb notebooks.
  4. Optional on macOS: open the Command Palette (Cmd+Shift+P) and run "Shell Command: Install 'code' command in PATH". You can then type code . in a terminal to open the current folder.
You want to…Windows / LinuxmacOS

4Install uv

Intuition. uv is one small, very fast program that replaces a whole drawer of older Python tools: pip, venv, pyenv, pip-tools and pipx.

uv is a Python package and project manager made by Astral and written in Rust. It is typically 10–100× faster than pip, and it does several jobs that used to need separate tools:

JobOlder tooluv command
Install packagespipuv add (or uv pip install)
Create virtual environmentspython -m venv, virtualenvuv venv (or automatically)
Install and switch Python versionspyenvuv python install, uv python pin
Lock exact versionspip-tools, Poetryuv lock (or automatically)
Run command-line tools in isolationpipxuvx / uv tool

Install commands

macOS and Linux: open Terminal and run:

curl -LsSf https://astral.sh/uv/install.sh | sh

Windows: open PowerShell (not Command Prompt) and run:

powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

Both download Astral's official installer script and run it. It puts uv and uvx in a folder in your home directory (~/.local/bin on macOS/Linux) and adds that folder to your PATH: the list of folders your terminal searches when you type a command name.

Alternatives, if you prefer a package manager: brew install uv (macOS Homebrew) or winget install --id=astral-sh.uv -e (Windows).

Check it worked

Close the terminal and open a new one (so it picks up the new PATH), then:

uv --version
# uv 0.11.x (…)

"command not found: uv" straight after installing? The terminal you used was opened before PATH changed. Open a new terminal (or restart VS Code). On macOS/Linux you can also run source $HOME/.local/bin/env in the current terminal.

To update uv later (if you used the installer script): uv self update. With Homebrew, use brew upgrade uv instead.

You do not need to install Python separately. If a project needs a Python version you don't have, uv downloads a suitable one automatically.

5Start a project: uv init

Intuition. uv init creates a new project folder with a "label on the box" (pyproject.toml) that says what the project is and what it needs.

uv init demo        # creates a new folder called demo/
cd demo

# or, inside an existing empty folder:
uv init

Output:

Initialized project `demo` at `/Users/you/projects/demo`

├── .python-version
├── README.md
├── main.py
└── pyproject.toml

pyproject.tomlThe project's settings: name, version, required Python version and the list of dependencies. The standard Python project file, read by many tools.Yes

main.pyA tiny "Hello from demo!" script to prove everything works. Rename or delete it.Your choice

Note what is not created yet: no .venv and no uv.lock. They appear the first time you run uv venv, uv add, uv run or uv sync.

The new pyproject.toml

[project]
name = "demo"
version = "0.1.0"
description = "Add your description here"
readme = "README.md"
requires-python = ">=3.12"
dependencies = []

requires-python is set from the Python version uv picked (normally the newest one you have). dependencies is empty until you uv add something. TOML is a simple configuration-file format: [section] headings, then key = value lines.

Useful options: uv init --python 3.12 demo starts the project on Python 3.12 (see section 10). uv init --package demo creates a src/demo/ layout, useful when the project will be installed or imported as a package.

6Virtual environments: uv venv and activation

Intuition. uv venv builds the empty private garage (.venv). Activating it tells your current terminal "when I type python, use this one".

uv venv
Using CPython 3.12.13
Creating virtual environment at: .venv
Activate with: source .venv/bin/activate

Choose the Python version with uv venv --python 3.12. Without it, uv uses the version in .python-version.

Activating

ShellActivateDeactivate
macOS / Linux (bash, zsh)source .venv/bin/activatedeactivate
Windows PowerShell.venv\Scripts\activatedeactivate
Windows Command Prompt.venv\Scripts\activatedeactivate

Note the differences: bin and forward slashes on macOS/Linux, Scripts and backslashes on Windows. Once active, your prompt shows the environment name, for example (demo) you@laptop demo %. Check which Python you are using with which python (macOS/Linux) or where python (Windows): it should point inside .venv.

With uv you rarely need to activate. uv run, uv add and uv sync find and use the project's .venv automatically, and create it if it is missing. Activation is still handy when you want to type python or pytest directly, and VS Code activates it for you in its terminal.

Never edit or commit .venv. It is disposable: hundreds of megabytes of machine-specific files. If it gets into a mess, delete it and run uv sync to rebuild it in seconds.

7Managing dependencies: uv add, uv add --dev, uv remove

Intuition. uv add does three things in one go: writes the package into pyproject.toml, records exact versions in uv.lock, and installs it into .venv.

uv add pandas
Resolved 6 packages in 412ms
Prepared 4 packages in 1.21s
Installed 4 packages in 58ms
 + numpy==2.5.4
 + pandas==3.0.6
 + python-dateutil==2.9.0.post0
 + six==1.17.0

(Version numbers on your machine will differ: uv picks the newest versions that fit.) You asked for one package and got four: pandas's own dependencies came too. Resolving means working out a set of versions that are all compatible with each other.

pyproject.toml now contains:

dependencies = [
    "pandas>=3.0.6",
]

The >= is a version constraint: "this version or newer". The exact version actually installed is in uv.lock.

More ways to add

uv add pandas numpy matplotlib scikit-learn   # several at once
uv add "pandas<3"                             # with a constraint (quote it!)
uv add "pandas==2.2.3"                        # an exact version
uv add -r requirements.txt                    # everything listed in an old requirements file

uv add --dev pytest ipykernel ruff            # development-only tools
uv remove matplotlib                          # remove from pyproject.toml, uv.lock and .venv

Normal vs development dependencies

Normal: uv addDevelopment: uv add --dev
MeaningThe code needs it to runOnly people working on the code need it
Examplespandas, scikit-learn, fastapipytest, ruff, ipykernel, jupyterlab
Stored in[project] dependencies[dependency-groups] dev

    "ipykernel>=7.4.0",
    "pytest>=8.4.0",

Don't mix pip install into a uv project. pip install x (or uv pip install x) installs into the environment but does not update pyproject.toml or uv.lock. Your code works today, then breaks for your teammate, and for you the next time uv sync removes the unlisted package. In a uv project, always use uv add.

8Running code: uv run

Intuition. uv run means "make sure the environment is up to date, then run this command inside it". No activation, no forgetting.

uv run python main.py          # run a script
uv run main.py                 # shorter: uv knows .py files need Python
uv run python                  # an interactive Python prompt in the project's environment
uv run pytest                  # run a tool installed in the environment
uv run jupyter lab             # start Jupyter from the environment

Every time, before running your command, uv run:

  1. finds the project (the nearest pyproject.toml in this folder or a parent folder);
  2. creates .venv if it doesn't exist;
  3. checks that uv.lock matches pyproject.toml and that .venv matches uv.lock, fixing either if needed;
  4. runs the command with the environment's Python.

So if a teammate pushes a new dependency and you pull it, uv run simply installs it before running. This is why uv run is the recommended habit.

One-off tools: uvx ruff check . runs a tool in a temporary, isolated environment without adding it to your project (the uv version of pipx run). uv run --with rich script.py adds a package for that one run only.

9uv sync and uv.lock

Intuition. pyproject.toml is the shopping list ("pandas, version 3 or newer"). uv.lock is the receipt ("pandas 3.0.6, numpy 2.5.4, …"). uv sync makes your .venv match the receipt exactly.

pyproject.toml
what you asked for
(you edit, via uv add)
→ uv lock →
uv.lock
exact versions
(uv writes it)
→ uv sync →
.venv
what is installed
(never commit)

What uv sync does

  • Creates .venv if missing (with the right Python version, downloading it if needed).
  • Updates uv.lock if pyproject.toml changed.
  • Installs exactly the locked versions, and removes anything not in the lock file. That makes it an "exact" sync: stray packages don't survive.

The teammate workflow

git clone https://github.com/your-team/churn-model.git
cd churn-model
uv sync                 # creates .venv and installs the exact locked versions
uv run python train.py

Commit uv.lock to Git. It is what makes "works on my machine" work on every machine. It is cross-platform: one lock file covers macOS, Windows and Linux. Never edit it by hand.

Related commands

CommandWhat it does
uv lockUpdate uv.lock from pyproject.toml without installing anything.
uv lock --upgrade-package pandasMove pandas (only) to the newest version allowed by its constraint. Follow with uv sync.
uv lock --upgradeUpgrade everything that the constraints allow. Do this deliberately, and re-run your tests.
uv sync --lockedFail if uv.lock is out of date instead of updating it. Good for CI (automated checks).
uv sync --no-devInstall only normal dependencies, not the dev group.
uv treeShow the dependency tree: what depends on what.
uv export --format requirements-txtWrite the locked versions as a requirements.txt for tools that need one.

10Pinning a Python version

Intuition. Packages are built for particular Python versions. Pinning tells uv "this project uses Python 3.12", and uv fetches and uses exactly that.

uv python list           # versions installed, and versions available to download
uv python install 3.12   # download and install Python 3.12 (managed by uv)
uv python pin 3.12       # write "3.12" into .python-version for this project

After pinning, uv venv, uv sync and uv run all use 3.12. If .venv was built with a different version, uv rebuilds it on the next uv sync or uv run.

Why pin 3.12? The TensorFlow example

Large libraries with compiled code, such as TensorFlow, publish ready-built files (wheels) for specific Python versions only, and often take months to support a brand-new Python release. If your newest Python is too new, uv add tensorflow fails with "No solution found when resolving dependencies". Python 3.12 is widely supported by the data science and deep learning stack, so it is the safe choice for this course. Always check the versions listed on the library's PyPI page or install guide.

Gotcha: requires-python must allow the version you pin. If uv init wrote requires-python = ">=3.14", then uv python pin 3.12 fails with:

error: The requested Python version `3.12` is incompatible with the project `requires-python` value of `>=3.14`.

Fix: edit pyproject.toml to requires-python = ">=3.12" and pin again. Easier: start the project on 3.12 from the beginning with uv init --python 3.12 my-project, which sets both files for you.

    2.

    3.

    4.

    5. 
      
  5. Check the bottom-right status bar: it should show the Python version and .venv.
    6.

    7.

13Jupyter notebooks with uv

    
Intuition. A notebook runs on a kernel: a Python process started from some environment. To use your project's packages, the kernel must come from the project's .venv.

    
A kernel is the engine behind a notebook that actually runs each cell. ipykernel is the package that lets a Python environment act as a kernel. Two ways to work:


    

      

        
Option A: notebooks inside VS Code (recommended)


uv add --dev ipykernel

        
    
          
  1. Create or open a .ipynb file in VS Code.
    2. 
          
  2. Click Select Kernel (top right) → Python Environments → choose .venv.
    3. 
          
  3. Run a cell with import pandas to check.
    4. 
        

      

      

        
Option B: JupyterLab in the browser


uv add --dev jupyterlab
uv run jupyter lab

        
Opens JupyterLab at http://localhost:8888. Because it was started with uv run, its default kernel is the project's environment. (uv add jupyter installs the full Jupyter bundle: JupyterLab, classic Notebook and ipykernel.)

      

    


    
Other useful patterns


# Start JupyterLab without adding it to the project (temporary, for this run only)
uv run --with jupyter jupyter lab

# Register the project's environment as a named kernel for a Jupyter installed elsewhere
uv add --dev ipykernel
uv run python -m ipykernel install --user --name demo --display-name "Python (demo)"

    
Don't run !pip install in a notebook cell inside a uv project. It may install into a different Python from the kernel's, and it never updates pyproject.toml. Stop, run uv add package in the terminal, then restart the kernel.

    
After adding a package, restart the kernel. A running kernel imported its modules when it started. Use Restart in the notebook toolbar.

  


  
  

    
14Google Colab as an alternative

    
Intuition. Colab is someone else's computer running Jupyter in your browser: nothing to install, free GPUs, but it forgets everything when the session ends.

    
Google Colab (colab.research.google.com) gives you a hosted notebook with Python and common libraries (pandas, NumPy, scikit-learn, TensorFlow, PyTorch) already installed. You sign in with a Google account and start writing code.


# In a Colab cell: install an extra package for this session
%pip install lightgbm

# Keep files beyond the session by mounting Google Drive
from google.colab import drive
drive.mount("/content/drive")

    
%pip is a notebook "magic" command that installs into the kernel's own Python, which is safer than !pip, which runs as a shell command.

    

      
Good for
  • No local set-up: works on any laptop, even a Chromebook
  • Free (limited) GPU and TPU access for deep learning
  • Easy sharing, like a Google Doc
  • Quick experiments and teaching demos

      
Watch out for
  • The runtime resets after idling or a session limit: installed packages and files in /content are lost
  • You must re-run %pip install cells each session
  • Package versions are chosen by Google and change over time, so less reproducible
  • Not suitable for confidential data without approval; not a place to build an application

    

    
Rule of thumb for this programme: use a local uv project for anything you will keep, share in Git, or turn into an application. Use Colab for short experiments or when you need a free GPU.

16Recommended data science project structure

    
Intuition. A predictable layout means anyone (including you in three months) can find the data, the experiments and the reusable code without asking.

├── uv.lock               ← exact versions (commit)
├── .python-version       ← e.g. 3.12 (commit)
├── README.md             ← what it is, how to run it (commit)
├── .gitignore
├── .env.example          ← names of required settings, no real secrets (commit)
├── data/
│   ├── raw/              ← original data, never edited (usually NOT committed)

Intuition. Nine times out of ten the question is "which Python is running, and is the package installed in that one?"

18Cheat sheet

    
Intuition. Five commands cover almost everything: init once, add when you need a package, run to run, sync after cloning or pulling.

    

      
CommandWhat it does

      
        
curl -LsSf https://astral.sh/uv/install.sh | shInstall uv (macOS/Linux)

        
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"Install uv (Windows)

        
uv --version · uv self updateCheck / update uv

        
uv init my-projectNew project: pyproject.toml, .python-version, main.py, README.md, .gitignore, Git repo

        
uv init --python 3.12 my-projectNew project on Python 3.12

        
uv venvCreate .venv

        
source .venv/bin/activate · .venv\Scripts\activateActivate (macOS/Linux · Windows); deactivate to leave

        
uv add pandasAdd a dependency (pyproject.toml + uv.lock + .venv)

        
uv add --dev pytest ipykernelAdd development-only tools

        
uv remove pandasRemove a dependency

        
uv run main.py · uv run pytestRun inside the project environment (syncs first)

        
uv syncMake .venv match uv.lock exactly (after clone / pull)

        
uv lock --upgrade-package pandasUpgrade one package in the lock file

        
uv python install 3.12 · uv python pin 3.12Install a Python version · use it for this project

        
uv treeShow the dependency tree

        
uv run jupyter labStart JupyterLab with the project's packages

        
uvx ruff check .Run a tool once without installing it into the project

      
    

    
Daily routine: open the project folder in VS Code → git pull → uv sync → work, using uv add for new packages and uv run to run → commit pyproject.toml and uv.lock together.
