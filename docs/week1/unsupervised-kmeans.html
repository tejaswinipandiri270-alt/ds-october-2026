Unsupervised learning and K-Means clustering

How to find natural groups in data when nobody has told you the answers: what clustering is for, how K-Means works step by step, how to choose the number of clusters, how to prepare the data, how to turn clusters into business segments, and when to reach for a different algorithm.

1Supervised vs unsupervised learning

Intuition. In supervised learning you have the answers (labels) and teach the model to reproduce them. In unsupervised learning there are no answers: the model looks for structure on its own, such as groups of similar rows.

A label (or target) is the column you want to predict: "churned yes/no", "house price". A feature is an input column used to make the prediction: age, income, number of orders. Supervised learning needs both. Unsupervised learning only has features.

SupervisedUnsupervised
DataFeatures and a label for each rowFeatures only, no label
GoalPredict the label for new rowsDiscover structure: groups, patterns, unusual rows, a simpler representation
Typical tasksClassification ("which class?"), regression ("how much?")Clustering, dimensionality reduction, anomaly detection, association rules
Example algorithmsLogistic regression, decision trees, random forest, XGBoostK-Means, DBSCAN, hierarchical clustering, Gaussian mixtures, PCA
How you evaluateCompare predictions with the true labels (accuracy, F1, RMSE)No answer key. Use internal measures (inertia, silhouette), stability checks, and above all whether the result is useful
Business question"Will this customer churn?""What kinds of customers do we have?"
Main riskOverfitting, leakageFinding "groups" that are artefacts of scaling or of the algorithm, not real

They work well together. Clusters found without labels often become features for a later supervised model (for example "segment" as an input to a churn model), and a supervised model is often trained separately inside each segment.

2What clustering is, and what it's for

Intuition. Clustering sorts rows into groups so that rows in the same group are similar to each other and different from rows in other groups, like sorting a pile of laundry without being told the categories.

A cluster is a group of rows that are close together in feature space (the imaginary space where each feature is one axis). The algorithm gives each row a cluster label: just a number (0, 1, 2…) with no meaning of its own. You give the clusters meaning afterwards by studying what their members have in common (see Interpreting clusters).

Common business uses

Customer segmentation

Group customers by behaviour (spend, frequency, recency, channel) to tailor marketing, pricing or service. "Loyal big spenders" get a VIP offer; "lapsed customers" get a win-back email.

Grouping documents

Turn support tickets, reviews or articles into numeric vectors (TF-IDF or embeddings) and cluster them to discover topics: "delivery problems", "billing questions", "login issues", without reading every one.

Anomaly hints

Rows that sit far from every cluster centre, or that form tiny clusters of their own, are worth a closer look: possible fraud, faulty sensors, data-entry errors. Clustering gives hints; it is not a dedicated anomaly detector.

Image colour compression

Treat every pixel as a point with three features (red, green, blue). Cluster the pixels into, say, 16 colours and replace each pixel by its cluster centre. The image now needs a 16-colour palette instead of millions of colours.

Other uses: grouping shops or branches with similar sales patterns, grouping products that sell together, compressing many similar sensor readings, and creating a starting point for labelling data (label a few examples per cluster).

Hard vs soft clustering

  • Hard clustering gives each row exactly one cluster. K-Means is hard.
  • Soft clustering gives each row a probability of belonging to each cluster (for example 70% segment A, 30% segment B). Gaussian mixture models are soft.

There is no "correct" clustering. The same customers can be grouped by spending, by product taste or by geography, and each answer can be valid. The features you choose decide which structure the algorithm can find. A good clustering is one that is stable and useful for the decision you need to make.

3Distance and similarity, and why scaling matters

Intuition. "Similar" has to be turned into a number. Most clustering algorithms measure the distance between rows, and a feature with big numbers (income in pounds) will drown out a feature with small numbers (age in years) unless you put them on the same scale.

Measuring distance

MeasureFormula (two rows p and q)Plain EnglishUsed by
Euclidean√ Σ (pᵢ − qᵢ)²Straight-line distance "as the crow flies"K-Means (in fact it minimises squared Euclidean distance)
ManhattanΣ |pᵢ − qᵢ|Distance walking along a city grid; less affected by one big differenceK-Medians, DBSCAN (option)
Cosine distance1 − (p · q) / (‖p‖ ‖q‖)Compares direction, not size: two documents about the same topic are similar even if one is longerText and embeddings

Similarity is the opposite of distance: small distance = high similarity. K-Means uses Euclidean distance and cannot be switched to another measure in scikit-learn. If cosine similarity is what you want (for text), normalise each row to length 1 first: Euclidean distance on unit-length vectors ranks pairs the same way cosine does.

Worked example: income vs age

Three customers, two features:

CustomerAgeIncome
A30£40,000
B60£41,000
C31£45,000

Intuitively, A and C are the similar pair: nearly the same age and similar incomes. B is 30 years older. Now compute Euclidean distances on the raw numbers:

  • A to B: √(30² + 1,000²) ≈ 1,000.4
  • A to C: √(1² + 5,000²) ≈ 5,000.0

On raw numbers, A looks five times closer to B. A 30-year age gap counts for the same as a £30 income gap, so age has effectively been ignored. Now standardise each feature: subtract its mean and divide by its standard deviation, giving a z-score (how many standard deviations from average). Suppose age has a standard deviation of 12 years and income £15,000:

  • A to B: √((30/12)² + (1,000/15,000)²) = √(2.5² + 0.07²) ≈ 2.50
  • A to C: √((1/12)² + (5,000/15,000)²) = √(0.08² + 0.33²) ≈ 0.34

After scaling, C is the nearest neighbour of A, as common sense says. Both features now get a fair vote.

The data in original units

What K-Means "sees": both axes in the same units

Rule: always scale numeric features before K-Means (and before any other distance-based method: KNN, SVM, DBSCAN, hierarchical clustering). StandardScaler is the usual choice. Use RobustScaler if there are strong outliers. Tree-based models don't need scaling, but clustering almost always does.

4The K-Means algorithm, step by step

Intuition. Drop K pins on the map. Every point joins its nearest pin. Move each pin to the middle of its group. Repeat until nothing changes.

A centroid is the centre of a cluster: the average (mean) of all the points in it, feature by feature. K-Means is named after these: K clusters, each represented by its mean. The classic version is called Lloyd's algorithm.

  1. Choose K, the number of clusters. K-Means cannot work this out for you (see Choosing K).
  2. Initialise: place K starting centroids. The simplest way is to pick K random data points; the better way is k-means++.
  3. Assign step: compute the distance from every point to every centroid and give each point the label of its nearest centroid.
  4. Update step: move each centroid to the mean of the points now assigned to it.
  5. Repeat steps 3 and 4. Moving the centroids changes which centroid is nearest for some points, which changes the means again, and so on.
  6. Converge: stop when no point changes cluster (so the centroids stop moving), when the centroids move less than a small tolerance (tol), or after a maximum number of iterations (max_iter, 300 by default).

Clusters K:

Why it always stops

Both steps can only lower (or keep) the total squared distance from points to their centroids, called inertia:

  • The assign step moves a point only if another centroid is closer, so its squared distance can only fall.
  • The update step puts each centroid at the mean of its points, and the mean is exactly the position that minimises the sum of squared distances to a set of points.

There is only a finite number of ways to split the points into K groups, and inertia never goes up, so the algorithm must stop. But it stops at a local minimum: the best solution reachable from where it started, not necessarily the best solution overall. That is why initialisation matters.

What the boundaries look like

Each point goes to its nearest centroid, so the boundary between two clusters is the straight line (in more dimensions, a flat plane) exactly halfway between their centroids. The space is carved into convex "cells" around the centroids, known as a Voronoi diagram. This is the root of K-Means' main limitation: it can only produce compact, roughly round groups separated by straight boundaries.

Cost: each iteration computes n × K distances in d dimensions (n rows, d features), so K-Means is fast and scales to hundreds of thousands of rows. For millions of rows, MiniBatchKMeans updates the centroids from small random batches and is much faster, at a small cost in quality.

5Inertia (WCSS): what K-Means minimises

Intuition. Inertia measures how tightly packed the clusters are: add up, for every point, the squared distance to its own centroid. Smaller means tighter clusters.

Inertia, also called the within-cluster sum of squares (WCSS), is the quantity K-Means tries to make as small as possible:

WCSS = Σclusters k Σpoints x in cluster k ‖x − μk‖²

where μk (mu k) is the centroid of cluster k and ‖x − μk‖² is the squared Euclidean distance from point x to it. In scikit-learn it is stored in kmeans.inertia_ after fitting.

Worked example: one cluster on a number line with points 1, 2 and 6.

Centroid = (1 + 2 + 6) / 3 = 3. Squared distances: (1−3)² = 4, (2−3)² = 1, (6−3)² = 9. This cluster contributes 4 + 1 + 9 = 14 to the inertia. The total inertia is the sum of this over all clusters.

Why inertia always goes down as K goes up

  • With K = 1, inertia is the total spread of the data around its overall mean, the total sum of squares (TSS).
  • With K = n (one cluster per point), every point is its own centroid and inertia is 0.
  • In between, adding a cluster can never make the best possible solution worse: at the very least you could put the extra centroid on top of one point, reducing that point's distance to zero and leaving everyone else unchanged.

So you cannot choose K by picking the lowest inertia: that would always choose the largest K you try. Instead you look for the point where adding clusters stops helping much (the elbow). In practice a single run at K + 1 can occasionally come out slightly worse than at K, because each run only finds a local minimum; using n_init restarts makes this rare.

Other useful facts about inertia

  • It depends on scale and size. Inertia grows with the number of rows and with the units of the features. Compare inertia values only between runs on the same scaled data.
  • Total = within + between. TSS = WCSS + BCSS, where BCSS (between-cluster sum of squares) measures how far the centroids are from the overall mean. The ratio BCSS / TSS is the share of the total variation "explained" by the clusters.
  • It favours round clusters of similar spread, because squared distance to one centre is what it measures.
  • kmeans.score(X) returns the negative inertia of X (so that "higher is better" like other scikit-learn scores).

6Initialisation problems, k-means++ and n_init

Intuition. Where the pins start decides where they end. Start them spread out (k-means++), and try several starts and keep the best one (n_init).

The problem with random starts

If the starting centroids are K random data points, two of them can easily land in the same natural group while another group gets none. K-Means then gets stuck: one real group is split in two, and two other real groups are merged. Each step still lowers inertia, but only down to a poor local minimum. You can see this in the step-through widget: press "Initialise (random)" a few times and compare the final inertia.

k-means++: spread the starting centroids out

  1. Pick the first centroid uniformly at random from the data points.
  2. For every point, compute D(x): its distance to the nearest centroid chosen so far.
  3. Pick the next centroid at random, with probability proportional to D(x)². Points far from all existing centroids are much more likely to be chosen; points right next to one are very unlikely.
  4. Repeat steps 2–3 until K centroids are chosen, then run normal K-Means.

The starts are random but spread out, so each natural group is likely to get its own centroid. k-means++ also comes with a mathematical guarantee: on average its result is within a factor of about log K of the best possible inertia. It is the default in scikit-learn (init="k-means++"), which uses a "greedy" version that tries several candidates at each step and keeps the one that lowers inertia most.

n_init: run it several times and keep the best

Even k-means++ is random, so the safest approach is to run the whole algorithm several times from different starts and keep the run with the lowest inertia. That is what n_init does: n_init=10 runs K-Means 10 times and returns the best of the 10.

7Choosing K

Intuition. There is rarely one right answer. Use the elbow method and the silhouette score to find candidate values of K, then let the business decide which version is most useful.

The elbow method

Run K-Means for K = 1, 2, …, 10 and plot inertia against K. Inertia always falls, but at first it falls steeply (each new cluster separates a real group) and then it flattens (new clusters only split real groups into pieces). The bend in the curve, the elbow, is a good candidate for K.

The elbow is often unclear in real data: the curve can bend gradually with no obvious kink. Treat it as a hint, not a rule.

The silhouette score

The silhouette score asks, for every point: "am I much closer to my own cluster than to the next nearest cluster?"

  • a = the average distance from the point to the other points in its own cluster (how well it fits where it is).
  • b = the average distance from the point to the points in the nearest other cluster (the lowest such average among all other clusters).
s = (b − a) / max(a, b)

Each point gets a value between −1 and +1. The silhouette score of the whole clustering is the average over all points (silhouette_score in scikit-learn). A point alone in its cluster gets 0 by convention. It needs at least 2 clusters.

Value of sMeaning for a point
Close to +1Much closer to its own cluster than to any other: well clustered (a is small compared with b)
Around 0On the border between two clusters (a ≈ b)
NegativeCloser, on average, to another cluster than to its own: probably in the wrong cluster

Worked example: a point has a = 2 (average distance to its own cluster) and b = 6 (to the nearest other cluster). s = (6 − 2) / max(2, 6) = 4 / 6 ≈ 0.67: a well-placed point.

A common rule of thumb for the average score: above 0.7 strong structure, 0.5–0.7 reasonable, 0.25–0.5 weak (check whether it is useful), below 0.25 little real structure. Real customer data often scores 0.2–0.4 and can still be useful.

Choose the K with the highest average silhouette as a candidate. Unlike inertia, silhouette does not automatically improve with more clusters. It is slower to compute (every pair of points is compared), so on large data use silhouette_score(X, labels, sample_size=10000, random_state=42). Like inertia, it prefers compact, round, well-separated clusters.

Domain knowledge

The statistics suggest candidates; the business chooses. Questions to ask:

  • Can we act on K groups? A marketing team that can run four campaigns doesn't need twelve segments.
  • Can each cluster be described in one sentence? If two clusters have the same description, merge them (lower K). If one cluster contains obviously different kinds of customer, split it (higher K).
  • Is each cluster big enough to matter? A segment of 0.3% of customers may not justify its own strategy.
  • Is it stable? Rerun with a different random_state or on a different sample. If the clusters change a lot, the structure is weak.

Other internal measures you may meet: the Davies–Bouldin index (davies_bouldin_score, lower is better), the Calinski–Harabasz index (calinski_harabasz_score, higher is better) and the gap statistic. They all reward compact, well-separated clusters and should be read alongside the elbow and silhouette, not instead of judgement.

8Preprocessing for K-Means

Intuition. K-Means only sees distances between numbers. Anything that distorts those distances (different units, made-up numbers for categories, extreme values) distorts the clusters.

1. Choose the features deliberately

Every feature you include gets a vote in "similarity". Include only features that describe the kind of similarity you care about. For behavioural segmentation, use behaviour (spend, frequency, recency) and keep demographics aside to describe the segments afterwards. Drop ID columns, and drop near-duplicate features (spend in £ and spend in $) because they double-count the same thing.

2. Handle missing values

K-Means can't handle missing values. Impute them (median for numbers) or drop the rows, and consider adding a "was missing" flag if missingness itself means something.

3. Transform skewed features and handle outliers

A centroid is a mean, and means are pulled by extreme values. One customer who spent £2 million can drag a centroid towards them or end up as a cluster of one. Money and count features are usually right-skewed (a few very large values), so:

  • Apply a log transform (np.log1p) to skewed money and count features.
  • Cap extreme values at a percentile (for example the 1st and 99th), known as winsorising.
  • Use RobustScaler (based on the median and interquartile range) instead of StandardScaler.
  • Investigate genuine outliers separately rather than letting them shape the segments.

4. Scale

Standardise all numeric features so each has mean 0 and standard deviation 1 (StandardScaler). See the scaling widget for what happens if you don't. If one feature really should count more, you can multiply its scaled values by a weight, but do it on purpose.

5. Be careful with categorical features

K-Means needs numbers, and the mean of a category doesn't make sense.

  • Never code categories as 1, 2, 3 (London = 1, Leeds = 2, Bristol = 3): K-Means would treat Bristol as "further" from London than Leeds is, which is meaningless.
  • One-hot encoding (a 0/1 column per category) works for a few categories, but many 0/1 columns can dominate the distances, and centroids become fractions ("0.4 London") that are hard to interpret. Consider down-weighting them.
  • Often the better choice is to leave categories out of the clustering and use them afterwards to describe the clusters ("segment 2 is 70% London").
  • For mostly categorical data, use an algorithm designed for it: K-Modes (all categorical) or K-Prototypes (mixed), available in the third-party kmodes package, or hierarchical clustering with Gower distance.

6. Consider reducing dimensions

With many features (dozens or more), distances become less meaningful, because all points start to look roughly equally far apart (the "curse of dimensionality"). Removing irrelevant features or applying PCA before clustering often gives cleaner clusters.

import numpy as np
from sklearn.compose import ColumnTransformer

from sklearn.preprocessing import FunctionTransformer, StandardScaler, RobustScaler
from sklearn.impute import SimpleImputer

skewed = ["annual_spend", "orders_per_year"]          # illustrative column names

prep = ColumnTransformer([
    ("skewed", make_pipeline(SimpleImputer(strategy="median"),

9Interpreting and profiling clusters

Intuition. The algorithm only says "these customers belong together". Profiling answers "who are they?" so that each cluster becomes a segment with a name and an action.

A profiling routine

  1. Size: how many rows are in each cluster, and what share of the total? Very small clusters are often outliers.
  2. Averages: compute the mean (and median, for skewed features) of every feature per cluster, in the original units, not the scaled ones.
  3. Compare with the overall average: divide each cluster's mean by the overall mean. 1.8 means "80% above average"; 0.4 means "60% below". This shows what makes each cluster distinctive.
  4. Describe with extra columns: bring back columns you didn't cluster on (region, age band, acquisition channel) to describe each segment.
  5. Name each segment in plain language and agree an action for it.
  6. Check stability: rerun with different seeds or on another month's data. Segments that come and go are not ready for decisions.
# df has the original (unscaled) columns plus the cluster labels
df["segment"] = kmeans.labels_

profile = df.groupby("segment")[features].mean().round(1)
profile["customers"] = df["segment"].value_counts().sort_index()
profile["share_%"] = (100 * profile["customers"] / len(df)).round(1)
print(profile)

# Relative to the overall average: > 1 above average, < 1 below
print((df.groupby("segment")[features].mean() / df[features].mean()).round(2))

# Centroids back in original units (if StandardScaler was used)
centres = pd.DataFrame(scaler.inverse_transform(kmeans.cluster_centers_), columns=features)

10Limitations and alternatives

Intuition. K-Means assumes clusters are round blobs of similar size around a centre. When the real groups are rings, long strips, very different sizes, or full of noise, it will still return K groups, just the wrong ones.

Strengths

  • Simple to understand and explain
  • Fast; scales to large data (and MiniBatchKMeans to very large data)
  • Centroids are easy to interpret as "typical members"
  • Can assign new rows to existing clusters with predict

Weaknesses

  • You must choose K in advance
  • Assumes spherical, similar-sized clusters with similar spread
  • Sensitive to outliers (centroids are means) and to scaling
  • Depends on the starting centroids (local minima)
  • Numeric features only; Euclidean distance only
  • Every point is forced into a cluster; there is no "noise" label

11Evaluating clusters when you do have labels

Intuition. Sometimes you have a "known answer" for some rows (product category, fraud flag, a customer type from the CRM). Compare the clusters with it to see whether the algorithm rediscovered it, but remember cluster numbers don't line up with label names.

Crosstab: the cluster-by-label table

A crosstab (contingency table) counts how many rows of each true label fell into each cluster. Ideally each cluster is dominated by one label.

pd.crosstab(df["true_type"], df["segment"])

# segment       0    1    2
# true_type
# budget       12  180    5
# family        8   10  151
# premium     140    6    9

Here cluster 0 is mostly "premium", cluster 1 "budget" and cluster 2 "family": a good match, even though the numbers (0, 1, 2) say nothing by themselves.

Adjusted Rand index (ARI)

The adjusted Rand index compares two groupings by checking every pair of rows: do both groupings agree on whether the pair is together or apart? It is "adjusted" so that random labelling scores about 0.

  • 1.0 = identical groupings (cluster numbers can be swapped freely; only who-is-with-whom matters).
  • About 0 = no better than random. It can be slightly negative.
from sklearn.metrics import adjusted_rand_score, normalized_mutual_info_score

adjusted_rand_score(df["true_type"], df["segment"])          # 1.0 = perfect agreement
normalized_mutual_info_score(df["true_type"], df["segment"]) # 0 to 1, another common choice

# Stability check without any labels: compare two runs with different seeds
a = KMeans(n_clusters=4, n_init=10, random_state=1).fit_predict(X_scaled)
b = KMeans(n_clusters=4, n_init=10, random_state=2).fit_predict(X_scaled)
adjusted_rand_score(a, b)   # close to 1 = stable clusters

Don't use accuracy to compare clusters with labels: cluster 0 has no reason to correspond to label 0. And if you have labels for all the data and want to predict them, you have a supervised problem, so train a classifier instead.

12scikit-learn end to end: a customer segmentation example

Intuition. Scale → try several K → pick K → fit → read inertia, centroids and labels → profile → visualise.

The column names and the file below are illustrative: a made-up online retailer with one row per customer. Swap in your own data.

1. Prepare and scale

import pandas as pd
import matplotlib.pyplot as plt
from sklearn.preprocessing import StandardScaler
from sklearn.cluster import KMeans
from sklearn.metrics import silhouette_score

df = pd.read_csv("customers.csv")      # illustrative file
features = ["annual_spend", "orders_per_year", "avg_basket_value",
            "days_since_last_order", "tenure_months"]
X = df[features].dropna()

scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)     # mean 0, standard deviation 1 per column

2. Elbow and silhouette loop

ks = range(2, 11)
inertias, silhouettes = [], []
for k in ks:
    km = KMeans(n_clusters=k, n_init=10, random_state=42).fit(X_scaled)
    inertias.append(km.inertia_)
    silhouettes.append(silhouette_score(X_scaled, km.labels_))

fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(10, 4))
ax1.plot(ks, inertias, "o-");    ax1.set(xlabel="K", ylabel="Inertia (WCSS)", title="Elbow")
ax2.plot(ks, silhouettes, "o-"); ax2.set(xlabel="K", ylabel="Silhouette", title="Silhouette")
plt.show()

3. Fit the chosen model and read the results

kmeans = KMeans(n_clusters=4, init="k-means++", n_init=10, random_state=42)
kmeans.fit(X_scaled)

kmeans.labels_            # cluster number for each training row, e.g. array([2, 0, 0, 3, ...])
kmeans.cluster_centers_   # one row per cluster, in SCALED units
kmeans.inertia_           # WCSS of the best of the 10 runs
kmeans.n_iter_            # iterations the best run needed to converge

silhouette_score(X_scaled, kmeans.labels_)

centres = pd.DataFrame(scaler.inverse_transform(kmeans.cluster_centers_),
                       columns=features).round(1)   # back to £, days, months
print(centres)
Attribute / methodWhat it gives you
fit(X)Runs K-Means (n_init times) and keeps the best run
fit_predict(X)Fits and returns the labels in one call
predict(X_new)Labels new rows with their nearest centroid
transform(X)Distance from each row to every centroid (useful for anomaly hints: large distance to own centroid)
labels_Cluster of each training row
cluster_centers_Centroid coordinates, in the units the model was trained on
inertia_Within-cluster sum of squares of the final solution
n_iter_Number of iterations of the best run

PCA for 2-D visualisation

With five features you can't draw the clusters directly. Principal component analysis (PCA) creates new axes (principal components) that are combinations of the original features, ordered by how much of the data's variation they capture. Projecting the scaled data onto the first two components gives a 2-D scatter plot you can colour by cluster. Check pca.explained_variance_ratio_: if the two components capture, say, only 45% of the variation, clusters that overlap in the plot may still be well separated in the full data. Use PCA for looking; fit K-Means on the full scaled features unless you deliberately chose to cluster on the components.

from sklearn.decomposition import PCA

pca = PCA(n_components=2, random_state=42)
X_2d = pca.fit_transform(X_scaled)
print(pca.explained_variance_ratio_)          # e.g. [0.31, 0.24]

plt.scatter(X_2d[:, 0], X_2d[:, 1], c=kmeans.labels_, s=10, cmap="tab10")
centres_2d = pca.transform(kmeans.cluster_centers_)
plt.scatter(centres_2d[:, 0], centres_2d[:, 1], marker="X", s=200, c="black")
plt.xlabel("PC1"); plt.ylabel("PC2"); plt.show()

13Cheat sheet

TopicRemember
UnsupervisedNo labels; find structure. Judge results by stability and usefulness
K-Means loopChoose K → initialise → assign to nearest centroid → move centroid to mean → repeat until no change
Inertia / WCSSΣ squared distance from each point to its centroid. Lower = tighter. Always falls as K rises, so never choose K by minimum inertia
Local minimaResult depends on the start. Use init="k-means++" and n_init=10, set random_state
k-means++First centre random; each next centre chosen with probability ∝ D(x)², squared distance to the nearest chosen centre
ElbowPlot inertia vs K; pick where the curve bends. Often fuzzy
Silhouettes = (b − a) / max(a, b); −1 to 1; higher is better; pick K with the highest average
ScalingAlways scale (StandardScaler, or RobustScaler with outliers); log-transform skewed money/count features
CategoricalsNever code as 1, 2, 3. One-hot sparingly, or leave out and use for profiling; K-Prototypes for mixed data
ProfilingSize, means/medians in original units, ratio to overall mean, name and action per segment
Labels available?pd.crosstab and adjusted_rand_score (1 = identical, ≈ 0 = random); never accuracy
VisualisePCA to 2 components, colour by cluster; check explained variance
When not K-MeansOdd shapes or noise → DBSCAN/HDBSCAN · want a hierarchy → agglomerative · elliptical or overlapping clusters, soft membership → Gaussian mixture
 
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.cluster import KMeans
from sklearn.metrics import silhouette_score

pipe = make_pipeline(StandardScaler(), KMeans(n_clusters=4, n_init=10, random_state=42))
labels = pipe.fit_predict(X)
km = pipe[-1]
print(km.inertia_, silhouette_score(pipe[:-1].transform(X), labels))

A sensible workflow: choose features for the similarity you care about → clean, log-transform skewed columns, scale → run K = 2…10 with n_init=10 → shortlist K from elbow and silhouette → profile each candidate → pick the K the business can act on → check stability with another seed → document the segment names and refit schedule.
